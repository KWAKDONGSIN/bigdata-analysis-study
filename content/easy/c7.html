손실 함수와 옵티마이저 — 채점하는 자와 고치는 손

학습에는 두 명의 담당자가 필요해요. 예측이 얼마나 틀렸는지 점수를 매기는 손실 함수(loss function)와, 그 점수를 바탕으로 파라미터를 실제로 고치는 옵티마이저(optimizer)예요. 이 장에서는 MSE, nn.MSELoss(), optim.SGD, optimizer.step(), 학습률을 배워요. 샘플 시험 5번의 절반이 이 장이에요.

7-1. 손실 함수 — 틀린 정도를 숫자 하나로 ★★★

모델이 낸 예측값(prediction)과 정답(target)이 얼마나 다른지를 숫자 하나로 요약하는 함수가 손실 함수예요. 그 숫자가 loss예요. 예측이 정답과 같으면 loss는 0이고, 많이 틀릴수록 커져요.

비유 — 오답 점수 채점

시험을 채점해서 "틀린 정도"를 점수로 매기는 채점표라고 생각하세요. 점수가 낮을수록 잘 푼 거예요. 모델은 이 점수를 줄이는 방향으로 공부해요.

회귀(숫자를 맞히는 문제)에서 가장 많이 쓰는 손실이 평균제곱오차(MSE, Mean Squared Error)예요. 순서는 세 단계예요.

  1. 오차 = 예측 − 정답
  2. 오차를 제곱해요.
  3. 모두 더해서 개수로 나눠 평균을 내요.
MSE = (1/N) × Σ (예측 − 정답)² # N은 원소 개수

왜 제곱할까요? 오차 +2와 −2를 그냥 더하면 0이 돼서 "틀리지 않았다"고 착각하게 돼요. 제곱하면 부호가 사라져서 서로 상쇄되지 않고, 큰 오차에는 더 큰 벌점이 붙어요.

prediction = torch.tensor([3.0, 4.0]) target = torch.tensor([1.0, 5.0]) squared_error = (prediction - target) ** 2 manual_loss = squared_error.mean() # 직접 계산 criterion = nn.MSELoss() # 손실 함수 객체 library_loss = criterion(prediction, target) print("직접 계산한 MSE:", manual_loss.item()) print("nn.MSELoss 결과:", library_loss.item())
직접 계산한 MSE: 2.5 nn.MSELoss 결과: 2.5
코드 줄무슨 뜻
prediction - target[3−1, 4−5] = [2, −1]. 숫자별로 빼요.
** 2제곱해서 [4, 1]이 돼요.
.mean()(4 + 1) ÷ 2 = 2.5. 평균이에요.
criterion = nn.MSELoss()MSE 계산기를 하나 만들어요. 이름 criterion은 "기준"이라는 뜻이고 loss 담당 변수로 흔히 쓰는 이름이에요.
criterion(prediction, target)계산기를 함수처럼 불러요. 순서는 (예측, 정답)이에요. 결과는 직접 계산과 같은 2.5예요.

criterion(...)처럼 객체를 함수처럼 부를 수 있는 이유는 5장에서 배운 __call__ 덕분이에요. nn.MSELoss()도 nn.Module의 자식이라서 model(x)와 같은 방식이에요.

평균은 모든 원소 개수로 나눠요. 예를 들어 예측 [[1, 2], [3, 4]], 정답 [[1, 0], [3, 2]]이면 오차는 0, 2, 0, 2이고 제곱하면 0, 4, 0, 4예요. 합 8을 원소 4개로 나눠서 2.0이에요. 과제 1에서도 "(예측 − 목표)² 전체 원소 평균"으로 loss를 구했어요.

교수님 자료에는 nn.CrossEntropyLoss(), nn.SmoothL1Loss() 같은 다른 손실 함수도 있다고 이름만 나와요. 참고로 CrossEntropyLoss는 보통 분류 문제에 써요. 시험에서는 MSE만 정확히 알면 충분해요.

이렇게 고르세요 (풀이 요령)

MSE 결과를 묻는 문제는 ① 뺀다 ② 제곱한다 ③ 평균 낸다, 순서로 손으로 풀어요. 예를 들어 예측 [1, 2, 3], 정답 [2, 2, 5]이면 오차 [−1, 0, −2] → 제곱 [1, 0, 4] → 평균 5/3 = 약 1.67이에요. "합계"가 아니라 "평균"이라서 개수로 나누는 것을 잊지 마세요.

잠깐 확인 — 예측 [3, 4], 정답 [1, 5]의 MSE는? 그리고 criterion(prediction, target)에서 두 인자 순서는?

(4 + 1) ÷ 2 = 2.5예요. 순서는 (예측, 정답)이에요.

7-2. prediction과 target의 shape은 꼭 맞추기 ★★★

손실을 계산할 때 예측값과 정답의 크기(shape)가 같아야 해요. 크기가 다르면 오류가 나는 게 아니라 브로드캐스팅(작은 쪽을 늘려 맞추는 것)이 일어나서 엉뚱한 계산이 돼요. 에러 없이 경고만 나와서 더 위험해요. 교수님이 직접 만든 함정 문제예요.

prediction = torch.tensor([[2.0], [4.0], [6.0]]) # 크기 (3, 1) target = torch.tensor([1.0, 5.0, 4.0]) # 크기 (3,) print("prediction shape:", prediction.shape) print("target shape:", target.shape) print("뺄셈 결과 shape:", (prediction - target).shape) print("shape 안 맞춘 MSE:", nn.MSELoss()(prediction, target).item()) target = target.reshape(-1, 1) # (3,) → (3, 1) print("맞춘 뒤 target shape:", target.shape) print("shape 맞춘 MSE:", nn.MSELoss()(prediction, target).item())
prediction shape: torch.Size([3, 1]) target shape: torch.Size([3]) 뺄셈 결과 shape: torch.Size([3, 3]) shape 안 맞춘 MSE: 6.0 맞춘 뒤 target shape: torch.Size([3, 1]) shape 맞춘 MSE: 2.0
코드 줄무슨 뜻
(3, 1)과 (3,) 뺄셈크기가 달라서 3×3 표로 늘어나요. 예측 3개와 정답 3개를 모든 짝으로 비교해 9개가 돼요. 엉뚱한 비교예요.
nn.MSELoss()(prediction, target)경고가 뜨지만 계산은 돼서 틀린 값 6.0이 나와요.
target.reshape(-1, 1)(3,)를 (3, 1)로 바꿔요. -1은 "나머지는 알아서"라는 뜻이에요.
맞춘 뒤 MSE(1² + 1² + 2²) ÷ 3 = 6 ÷ 3 = 2.0이에요. 올바른 값이에요.

틀린 계산에서 9개의 제곱 오차는 이래요. 합이 54이고 9로 나눠서 6.0이 나온 거예요.

외우기 팁

Linear 모델의 출력은 (배치, 출력 개수)인 2차원이에요. 정답을 [1, 5, 4]처럼 1차원으로 만들면 안 맞아요. 정답도 (3, 1)로 reshape(-1, 1)해서 맞춰 주세요.

이렇게 고르세요 (풀이 요령)

prediction이 (3, 1)이고 target이 (3,)인 코드가 나오면 "shape을 맞추지 않아 의도와 다른 값이 나온다"가 정답이에요. 오류로 멈춘다는 보기는 틀려요. 경고만 나오고 잘못된 값이 계산돼요.

잠깐 확인 — prediction이 (3, 1), target이 (3,)일 때 뺄셈 결과의 shape은?

(3, 3)이에요. 두 크기가 달라서 브로드캐스팅으로 3×3으로 늘어나요.

7-3. 옵티마이저 — 기울기로 파라미터를 고치는 손 ★★★

6장에서 기울기를 구했어요. 이제 그 기울기로 파라미터를 실제로 바꾸는 담당자가 필요한데, 그게 옵티마이저예요. 6장에서 with torch.no_grad(): W -= lr * W.grad처럼 직접 쓰던 일을 대신해 줘요.

한 줄 정의

옵티마이저 = 자기에게 전달된 파라미터의 .grad를 이용해서 파라미터 값을 갱신하는 도구예요.

비유 — 채점표와 학생

loss는 채점표(몇 점 틀렸는지), 기울기는 선생님의 피드백(어느 방향으로 얼마나 고치라), 옵티마이저는 그 피드백대로 공부 방법을 실제로 바꾸는 학생이에요. 피드백을 받아도 학생이 움직이지 않으면 실력은 그대로예요.

가장 기본적인 방법이 SGD(Stochastic Gradient Descent, 확률적 경사 하강법)예요. 식은 6장에서 본 그대로예요.

w ← w − lr × (기울기) # lr은 학습률
import torch.optim as optim model = nn.Linear(1, 1) criterion = nn.MSELoss() optimizer = optim.SGD(model.parameters(), lr=0.02)
코드 줄무슨 뜻
import torch.optim as optim옵티마이저 모음을 불러와요. optim이라는 짧은 이름으로 써요.
model = nn.Linear(1, 1)모델을 먼저 만들어요. 그래야 넘겨줄 파라미터가 생겨요.
criterion = nn.MSELoss()손실 함수 객체예요.
optim.SGD(model.parameters(), lr=0.02)"이 파라미터들을 SGD 방식으로, 한 걸음 0.02로 고쳐라." 모델이 가진 모든 학습 대상이 한꺼번에 전달돼요.

여기서 5장의 등록이 중요해져요. model.parameters()에는 등록된 파라미터만 들어 있어서, nn.Parameter나 nn.Linear로 만들지 않은 일반 Tensor는 옵티마이저에 전달되지 않아 업데이트에서 빠져요.

순서가 헷갈린다고 교수님이 말했어요. 모델 → 손실 함수 → 옵티마이저 순서로 만들어요. 옵티마이저가 모델의 파라미터를 받아야 하기 때문이에요.

SGD 말고도 Adam, AdamW, RMSprop 같은 방법이 있어요. 교수님은 SGD가 현재 weight에서 기울기(에 학습률을 곱한 값)를 빼는 간단한 방식이고, 다른 방식들은 이전 기울기를 기억해서 쓰는 등 더 복잡한 규칙을 쓴다고 설명했어요. 어떤 규칙을 쓰는지에 따라 필요한 설정값이 달라요. 시험에서는 이름과 "갱신 규칙이 다르다"만 알면 돼요.

이렇게 고르세요 (풀이 요령)

옵티마이저 설명 보기에서는 "전달된 파라미터의 .grad를 이용해 파라미터를 갱신한다"가 맞아요. optim.SGD(model.parameters(), lr=...)를 만드는 시점에는 아무것도 바뀌지 않는다는 점도 기억하세요.

잠깐 확인 — optimizer = optim.SGD(...)를 실행한 직후 모델의 weight는 바뀔까요?

바뀌지 않아요. 옵티마이저를 만드는 것은 "이 방식으로 고치겠다"는 설정만 하는 거예요. 값이 바뀌려면 backward로 기울기를 구한 다음 step()을 불러야 해요.

7-4. backward()는 계산, step()은 갱신 — 역할 분담 ★★★

샘플 시험 5번의 핵심이에요. 두 함수는 하는 일이 완전히 달라요. 값이 어떻게 바뀌는지 직접 보면 가장 확실해요. 교수님 자료의 기본 실습 5번이에요. 가중치 1.0짜리 모델에 입력 2, 정답 4를 넣고 학습률 0.1로 한 번 학습해요.

model = nn.Linear(1, 1, bias=False) with torch.no_grad(): model.weight.fill_(1.0) # weight를 1.0으로 고정 X = torch.tensor([[2.0]]) target = torch.tensor([[4.0]]) criterion = nn.MSELoss() optimizer = optim.SGD(model.parameters(), lr=0.1) optimizer.zero_grad() prediction = model(X) loss = criterion(prediction, target) print("업데이트 전 weight:", model.weight.item()) print("업데이트 전 loss:", loss.item()) loss.backward() print("backward 직후 weight:", model.weight.item()) print("weight.grad:", model.weight.grad.item()) optimizer.step() print("step 직후 weight:", round(model.weight.item(), 2)) print("업데이트 후 loss:", round(criterion(model(X), target).item(), 2))
업데이트 전 weight: 1.0 업데이트 전 loss: 4.0 backward 직후 weight: 1.0 weight.grad: -8.0 step 직후 weight: 1.8 업데이트 후 loss: 0.16
코드 줄무슨 뜻
nn.Linear(1, 1, bias=False)입력 1개, 출력 1개, 편향 없음. 학습할 숫자는 weight 하나뿐이에요.
model.weight.fill_(1.0)weight를 1.0으로 채워요. 손으로 풀기 쉽게 정한 값이에요.
prediction = model(X)1.0 × 2 = 2
loss = criterion(...)(2 − 4)² = 4
loss.backward()기울기를 계산해요. 2 × (2 − 4) × 2 = −8. 하지만 weight는 아직 1.0 그대로예요.
optimizer.step()저장된 기울기로 갱신해요. 1.0 − 0.1 × (−8) = 1.8
업데이트 후 loss예측 1.8 × 2 = 3.6, 오차 (3.6 − 4)² = 0.16. 4에서 0.16으로 줄었어요.

세 줄을 따로 보면 이렇게 나눠져요.

함수하는 일weight 값은?
optimizer.zero_grad()저장된 기울기를 지워요 (비워요)안 바뀌어요
loss.backward()기울기를 계산해서 .grad에 저장해요안 바뀌어요
optimizer.step()저장된 기울기로 파라미터를 갱신해요여기서 바뀌어요

step()은 기울기를 새로 계산하지도, 지우지도 않아요. 이미 저장된 .grad를 읽어 값을 고치기만 해요. 그래서 step() 전에 backward()가 꼭 있어야 하고, 다음 반복 전에는 기울기를 지워 줘야 해요. (참고로 요즘 PyTorch는 zero_grad()가 기울기를 0 대신 "없음(None)"으로 비워요. 지워서 새로 시작한다는 의미는 같아요.)

이렇게 고르세요 (풀이 요령)

샘플 5번 보기를 이 표로 하나씩 지워 보세요. "optimizer.step()은 저장된 기울기를 이용해 파라미터를 갱신한다"가 맞아요. "loss.backward()가 파라미터 값까지 갱신한다", "zero_grad()가 파라미터를 0으로 만든다", "criterion이 이전 기울기를 초기화한다", "step()이 기울기를 새로 계산한다"는 모두 틀려요. 계산은 backward, 갱신은 step, 비우기는 zero_grad, 점수 매기기는 criterion이에요.

잠깐 확인 — loss.backward() 직후와 optimizer.step() 직후 중 weight 값이 바뀌는 시점은?

optimizer.step() 직후예요. backward 직후에는 기울기(.grad)만 채워지고 weight는 그대로예요.

7-5. 학습률(learning rate) — 한 걸음의 크기 ★★

학습률(lr, η)은 기울기를 얼마나 크게 반영해서 파라미터를 고칠지 정하는 값이에요. 식 w ← w − lr × 기울기에서 lr이 클수록 한 번에 크게 움직여요.

비유 — 내려오는 보폭

골짜기로 내려가는데 보폭이 너무 작으면 해가 질 때까지 못 내려가고, 너무 크면 골짜기를 뛰어넘어서 반대쪽 더 높은 곳에 떨어져요. 적당한 보폭이 필요해요.

7-4의 같은 문제(weight 1, 입력 2, 정답 4)를 학습률만 바꿔서 한 번 업데이트하면 이렇게 돼요. 기울기는 모두 −8이에요. 직접 실행해서 확인한 값이에요.

lr새 weight (1 − lr × (−8))새 loss결과
0.011.08약 3.39너무 작아요. 거의 안 줄어요
0.11.80.16적당해요
0.253.04.0정답(2)을 지나쳐 제자리예요
0.55.036.0오히려 훨씬 커졌어요

정답 weight는 2예요(2 × 2 = 4). lr = 0.1이면 반복할수록 1.8 → 1.96 → 1.992 → 1.998 → 2.0으로 정답에 다가가요. 반면 lr = 0.5이면 5 → −7 → 29 → −79 → 245로 점점 더 크게 튀어서 학습이 망가져요. 이것을 발산이라고 해요. 이렇게 커지다 보면 loss가 NaN이나 Inf(무한대)로 나오기도 해요.

반대로 lr = 0이면 아무리 step을 해도 weight가 바뀌지 않아요. 교수님 자료의 오류 점검표에도 parameter가 안 변하는 원인으로 step() 누락, optimizer에 파라미터 미등록, lr=0, 기울기 0이 나와요.

증상원인

loss가 NaN 또는 Inflr이 너무 커요 / 입력값이 이상해요 / 0으로 나눴어요
loss가 안 줄어요lr, 데이터, 학습 순서를 점검해요
이렇게 고르세요 (풀이 요령)

학습률 문제는 "너무 크면 발산, 너무 작으면 느림" 한 문장으로 풀려요. 또 "학습 후 weight가 안 변했다"는 상황은 step 누락, lr=0, 파라미터 미등록 중에서 골라요.

잠깐 확인 — 학습률을 너무 크게 하면 loss는 어떻게 될까요?

줄어들지 않고 오히려 커지거나 NaN이 될 수 있어요. 한 걸음이 너무 커서 정답을 지나쳐 반대쪽으로 더 멀리 가기 때문이에요.

7-6. 손으로 연습하기 — 점수 계산과 한 번의 업데이트

시험은 "결과 예측" 유형이 나오니 두 가지를 손으로 계산해 보세요. 풀이도 같이 적었어요.

연습 1 — 예측 [1., 2., 3.], 정답 [2., 2., 5.]일 때 nn.MSELoss()의 값은?

  • 오차 = [−1, 0, −2]
  • 제곱 = [1, 0, 4]
  • 평균 = 5 ÷ 3 = 약 1.67 (실행 결과 tensor(1.6667))

연습 2 — weight가 0.5이고 기울기가 4일 때, 학습률 0.1로 optimizer.step()을 한 번 하면 weight는?

  • 0.5 − 0.1 × 4 = 0.1
  • 기울기가 양수니까 weight가 줄어요.

연습 3 — 아래 코드에서 step() 직전 weight.grad와 직후 weight는? (weight=1, 입력 2, 정답 4, lr=0.1)

  • 직전 weight.grad = −8
  • 직후 weight = 1.8

자주 헷갈리는 세트를 마지막으로 정리해요.

이름역할한 줄 코드
손실 함수 (criterion)틀린 정도를 점수로loss = criterion(prediction, target)
backward기울기 계산loss.backward()
옵티마이저 (optimizer)기울기로 파라미터 갱신optimizer.step()
학습률 (lr)한 걸음의 크기optim.SGD(..., lr=0.1)
이렇게 고르세요 (풀이 요령)

숫자 결과 문제는 "예측값 → loss → 기울기 → 새 weight" 순서로 한 줄씩 계산하세요. 중간 숫자(예 예측 2, loss 4, 기울기 −8)를 종이에 적어 가면 실수가 줄어요.

잠깐 확인 — 옵티마이저는 모델을 만들기 전에 만들 수 있을까요?

없어요. 옵티마이저는 model.parameters()를 받아야 하는데 모델을 만들기 전에는 파라미터가 존재하지 않아요. 모델 → criterion → optimizer 순서예요.

이 장 3줄 요약
  • 손실 함수는 예측과 정답의 차이를 숫자 하나로 만들어요. MSE는 (예측 − 정답)²의 평균이고(예 [3, 4]와 [1, 5]이면 2.5), criterion(예측, 정답)의 두 크기(shape)는 같아야 해요(안 맞추면 브로드캐스팅으로 틀린 값이 나와요).
  • 옵티마이저 optim.SGD(model.parameters(), lr=...)는 파라미터의 .grad로 값을 갱신해요. backward()는 기울기 계산, step()은 갱신만 해요(w=1, 입력 2, 정답 4, lr=0.1이면 기울기 −8, 새 weight 1.8, loss 4 → 0.16).
  • 학습률은 한 걸음의 크기예요. 너무 크면 발산(NaN, Inf)하고 너무 작으면 느려요. SGD 외에 Adam, AdamW, RMSprop도 있고 갱신 규칙만 달라요.
