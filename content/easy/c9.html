학습 루프와 검증 — 지금까지 배운 것을 한 줄로 이어서 반복하기

5장의 모델, 6장의 기울기, 7장의 손실과 옵티마이저, 8장의 배치가 모두 한곳에 모이는 장이에요. 핵심은 한 배치를 학습하는 5줄(zero_grad → forward → loss → backward → step)이고, 이것을 배치마다, epoch마다 반복하는 것이 학습 루프예요. 샘플 시험 5번이 바로 이 5줄이에요.

9-1. 학습의 큰 그림과 한 배치 5줄 ★★★

교수님이 "딥러닝 모델 Training 과정" 자료에서 정리한 학습의 큰 흐름은 이래요.

  1. 데이터 준비 — 입력 x와 정답 T
  2. Forward — 모델에 x를 넣어 예측 ŷ를 얻어요.
  3. Loss — ŷ와 정답을 비교해 틀린 정도를 숫자 하나로 만들어요.
  4. Gradient — 각 weight를 어느 쪽으로 바꾸면 loss가 줄어드는지(기울기)를 구해요.
  5. Update — 기울기의 반대 방향으로 weight를 조금 고쳐요.
  6. 다른 배치로 2~5를 계속 반복해요.
비유 — 양궁 연습

화살을 쏘고(forward), 과녁에서 얼마나 빗나갔는지 보고(loss), 어느 쪽으로 조준을 고쳐야 할지 판단하고(gradient), 실제로 조준을 고쳐요(update). 그리고 이전 판단은 잊고 다시 쏴요(zero_grad). 이 한 사이클을 수없이 반복하는 것이 학습이에요.

이 흐름을 코드로 쓰면 딱 5줄이에요. 5개를 순서대로 외워 두세요.

optimizer.zero_grad() # 1. 기울기 지우기 prediction = model(batch_x) # 2. forward로 예측 loss = criterion(prediction, batch_y) # 3. loss 계산 loss.backward() # 4. 기울기 계산 optimizer.step() # 5. 파라미터 갱신
순서코드하는 일값이 바뀌는 곳
1optimizer.zero_grad()지난 step의 기울기를 비워요.grad만 비워지고 weight는 그대로
2prediction = model(batch_x)모델이 예측값을 계산하고 계산 그래프를 만들어요weight, grad 모두 그대로
3loss = criterion(prediction, batch_y)예측과 정답을 비교해 숫자 하나(loss)를 만들어요weight, grad 모두 그대로
4loss.backward()각 파라미터의 기울기를 계산해서 .grad에 저장해요.grad가 채워져요 (weight는 그대로)
5optimizer.step()저장된 기울기로 파라미터를 갱신해요weight가 바뀌어요

왜 zero_grad가 맨 앞일까요? 6장에서 배운 것처럼 기울기는 쌓이기 때문에, 지난 step의 값을 지우고 시작해야 이번 step의 기울기만 정확히 담겨요. 교수님은 zero_grad를 backward 전에만 하면 된다고 했어요. backward 뒤에 하면 방금 구한 기울기가 사라지기 때문이에요. 관례는 맨 앞에 두는 거예요.

왜 forward와 loss를 매번 다시 할까요? 6장에서 본 것처럼 계산 그래프는 backward를 하면 풀려요. 매 반복마다 model(x)와 criterion(...)을 새로 실행하니까 새 그래프가 만들어져서 문제가 없어요. 또 업데이트된 weight로 새로 계산해야 다음 예측이 나아져요.

5줄 중 하나를 빼먹으면 이런 일이 생겨요. 교수님 자료의 오류 점검표예요.

빼먹은 것결과
zero_grad()기울기가 계속 쌓여서 실제보다 커져요. 업데이트가 이상해져요.
forward / lossbackward할 loss가 없어요(또는 지난 loss를 다시 써서 오류).
backward().grad가 비어 있어서 step()이 갱신할 것이 없어요. weight 불변.
step()기울기는 구했지만 weight가 안 바뀌어요. 학습이 안 돼요.
외우기 팁

"지우고 → 예측하고 → 채점하고 → 기울기 구하고 → 고친다". 영어로는 zero_grad → forward → loss → backward → step이에요. 교수님 슬라이드가 "핵심 한 줄"이라고 부른 순서예요.

이렇게 고르세요 (풀이 요령)

5줄이 나오면 각 줄에 한 단어를 붙여 보세요. 지우기(zero_grad), 예측(model), 점수(criterion), 기울기 계산(backward), 갱신(step). 보기가 "이 함수가 하는 일"을 다르게 말하면 오답이에요. 특히 backward = 계산, step = 갱신을 바꿔 놓은 보기가 자주 나와요.

잠깐 확인 — 학습 5단계에서 weight 값이 실제로 바뀌는 줄은 몇 번째일까요?

5번째 optimizer.step()이에요. backward까지는 기울기(.grad)만 만들어져요.

9-2. epoch 반복 — 같은 데이터를 여러 바퀴 ★★

한 번 업데이트하는 것만으로는 원하는 weight를 얻기 어려워요. 학습률만큼만 조금씩 움직이기 때문이에요. 그래서 같은 학습 데이터를 여러 번 사용하면서 5줄을 반복해요. 전체 데이터를 한 번 쓴 횟수가 epoch이에요.

교수님 노트북의 예제예요. 정답이 y = 2x + 1인 데이터 5개를 nn.Linear(1, 1)에 학습시켜서, 처음엔 랜덤이던 weight와 bias가 2와 1에 가까워지는지 봐요. 데이터가 5개뿐이라 전부 한 번에 넣어요. 그러면 한 epoch이 한 step이에요.

x_train = torch.arange(-2.0, 3.0).reshape(-1, 1) # [-2, -1, 0, 1, 2], 크기 (5, 1) y_train = 2 * x_train + 1 # 정답: [-3, -1, 1, 3, 5] model = nn.Linear(1, 1) criterion = nn.MSELoss() optimizer = optim.SGD(model.parameters(), lr=0.02) for epoch in range(201): optimizer.zero_grad() prediction = model(x_train) loss = criterion(prediction, y_train) loss.backward() optimizer.step() if epoch % 20 == 0: print( f"epoch={epoch:3d} loss={loss.item():.6f} " f"w={model.weight.item():.4f} b={model.bias.item():.4f}" )

nn.Linear(1, 1)입력 1개, 출력 1개. weight와 bias가 하나씩 있고 처음에는 랜덤 값이에요.

loss.item()loss Tensor에서 순수한 숫자를 꺼내요.

위 출력 숫자는 교수님 노트북에서 나온 거예요. 결과를 보면 loss는 20.23에서 0에 가까워지고, weight는 −0.72에서 2에, bias는 −0.60에서 1에 가까워져요. 시작 값이 랜덤이라 처음 숫자는 실행할 때마다 조금 달라요. 학습이 끝난 모델에 새 입력 5와 10을 넣으면 약 11과 21이 나와요(2×5+1, 2×10+1).

자료의 심화 실습은 같은 방식으로 y = 3x − 2를 200 epoch 학습해요. 학습에 쓰지 않은 x = 3.0을 넣으면 정답 7에 가까운 값이 나와요. 이때 최종 weight가 정확히 3, −2가 아니라 가까운 값이어도 되는 이유는 학습 횟수가 유한하고 컴퓨터 계산에 미세한 오차가 있기 때문이에요. 또 optimizer는 반복문 밖에서 한 번만 만들어요.

이렇게 고르세요 (풀이 요령)

학습 루프에서 "range(201)이면 step이 몇 번인가"는 전체 데이터를 한 번에 넣을 때 201번이에요. 학습이 잘 되면 loss는 줄어들어요. 그래서 학습 전후 loss 비교 문제에서는 "학습 후 loss가 더 작다"를 고르세요. 또 zero_grad()를 매 epoch 실행하는 이유는 이전 기울기의 누적을 막기 위해서예요.

잠깐 확인 — 학습이 잘 진행되면 epoch이 늘수록 loss는 어떻게 변하나요?

0에 가까워져요. 위 예제에서도 20.23에서 거의 0으로 줄어들었어요.

9-3. 배치로 나눠 학습하기 — 반복문 안의 반복문 ★★★

데이터가 많으면 8장의 DataLoader로 배치를 만들어서 쓰고, 5줄을 배치마다 실행해요. 그래서 반복문이 2겹이 돼요. 바깥은 epoch, 안쪽은 배치예요.

교수님 노트북의 코드예요. sample 90개를 배치 20개씩 묶어서 30 epoch 학습해요.

torch.manual_seed(0) # 난수를 고정해서 매번 같은 결과가 나오게 해요 x_train = torch.linspace(-2.0, 2.0, steps=90).reshape(-1, 1) y_train = 2 * x_train + 1 train_dataset = TensorDataset(x_train, y_train) train_loader = DataLoader(train_dataset, batch_size=20, shuffle=True, drop_last=False) class MyModel(nn.Module): def __init__(self): super().__init__() self.fc = nn.Linear(1, 1) def forward(self, x): return self.fc(x) model = MyModel() criterion = nn.MSELoss() optimizer = optim.SGD(model.parameters(), lr=0.02) for epoch in range(30): total_loss = 0.0 total_samples = 0 for batch_x, batch_y in train_loader: optimizer.zero_grad() prediction = model(batch_x) loss = criterion(prediction, batch_y) loss.backward() optimizer.step() batch_samples = batch_x.size(0) total_loss += loss.item() * batch_samples total_samples += batch_samples epoch_loss = total_loss / total_samples print(f"epoch={epoch+1} 평균 loss={epoch_loss:.6f} " f"w={model.fc.weight.item():.4f} b={model.fc.bias.item():.4f}")

코드 줄무슨 뜻
torch.manual_seed(0)랜덤 값을 고정해요. 그래서 처음 weight와 섞는 순서가 같아져 아래 출력과 똑같은 결과를 얻어요.
torch.linspace(-2.0, 2.0, steps=90)-2부터 2까지 같은 간격으로 90개 숫자를 만들어요. sample 90개예요.
TensorDataset(x_train, y_train)입력과 정답을 짝지어 Dataset으로 만들어요. (8장)
DataLoader(..., batch_size=20, shuffle=True)20개씩 묶고 epoch마다 섞어요. 90 ÷ 20 = 4.5이니 배치는 5개(20, 20, 20, 20, 10)예요.
self.fc = nn.Linear(1, 1)5장의 모델 클래스예요. 층 한 개를 가져요.
for epoch in range(30):바깥 반복. 데이터 전체를 30번 돌아요.
for batch_x, batch_y in train_loader:안쪽 반복. 이 for 문 한 번을 끝까지 돌면 1 epoch이에요. 한 epoch에 5번 돌아요.
5줄배치마다 실행돼요. 그러니 weight는 한 epoch에 5번 업데이트돼요.
total_loss, total_samplesepoch의 loss 합계와 사용한 sample 수를 모아요. 다음 절에서 설명해요.

weight가 업데이트되는 횟수를 세 보면 5 × 30 = 150번이에요. 데이터를 한꺼번에 넣었던 앞 예제(1 epoch에 1번)와 달라요. 한 epoch 안에서 업데이트가 여러 번 일어난다는 점이 다른 거예요. 결과도 30 epoch 만에 w가 2에, b가 1에 매우 가까워졌어요. 교수님 자료에서는 weight가 한 번 업데이트될 때마다 1 iteration이라고 해요(여기서 말하는 step과 같은 뜻이에요). 전체 데이터를 한 바퀴 쓰면 1 epoch이에요.

이렇게 고르세요 (풀이 요령)

step 횟수 문제는 "한 epoch의 배치 수 × epoch 수"로 풀어요. sample 90개, batch_size 20, 30 epoch이면 5 × 30 = 150이에요. 배치 수는 8장처럼 올림(4.5 → 5)이에요. 또 "for batch_x, batch_y in loader 안에 5줄이 있다"는 보기는 배치마다 업데이트한다는 뜻이에요.

잠깐 확인 — sample 100개, batch_size 25, 10 epoch이면 weight는 모두 몇 번 업데이트될까요?

배치 수 4(100 ÷ 25) × 10 = 40번이에요.

9-4. epoch 평균 loss — 마지막 배치가 작을 때 ★★

한 epoch이 끝나면 "이번 epoch의 평균 loss"를 보고 싶어요. 그런데 단순히 배치 loss들을 평균 내면 안 돼요. 배치 크기가 다르면(예 20, 20, 20, 20, 10) sample이 적은 마지막 배치가 같은 비중으로 계산돼서 값이 틀어져요. 그래서 교수님은 "각 배치 loss에 그 배치의 sample 수를 곱해서 모두 더한 뒤, 전체 sample 수로 나눈다"고 했어요.

비유 — 반별 평균 점수

1반 학생이 40명, 2반이 10명이에요. 두 반의 평균이 각각 80점, 60점일 때 전교 평균은 (80+60)/2 = 70점이 아니라 (80×40 + 60×10)/50 = 76점이에요. 인원이 많은 반이 더 크게 반영돼야 하기 때문이에요. 배치 loss도 똑같아요.

배치 3개의 크기가 4, 4, 2이고 각각의 평균 loss가 3, 6, 9라고 해 봐요.

방법계산결과
단순 평균 (틀림)(3 + 6 + 9) ÷ 36.0
sample 수로 가중 (맞음)(3×4 + 6×4 + 9×2) ÷ 10 = (12 + 24 + 18) ÷ 105.4

코드의 해당 줄은 이래요.

batch_samples = batch_x.size(0) # 이 배치의 sample 수 total_loss += loss.item() * batch_samples # loss × sample 수를 계속 더함 total_samples += batch_samples # 사용한 sample 수를 계속 더함 ... epoch_loss = total_loss / total_samples # epoch 끝에서 한 번 나눔
코드 줄무슨 뜻
batch_x.size(0)batch_x의 첫 번째 차원 크기예요. 이 배치에 sample이 몇 개인지 알려 줘요. (4, 2)이면 4.
loss.item()그 배치의 평균 loss(숫자 하나)예요.
loss.item() * batch_samples평균에 개수를 다시 곱해서 그 배치의 loss 총합으로 되돌려요.
total_loss / total_samples모든 loss 총합을 전체 sample 수로 나눠서 올바른 epoch 평균을 구해요.

이것은 학습(backward, step)에는 영향이 없고 기록용이에요. 숫자만 필요하니까 .item()으로 순수 숫자를 꺼내서 쌓아요. 교수님은 "어려운 수학은 아니고 산수"라고 했어요. 시험에는 개념으로 나올 수 있으니 왜 이렇게 하는지만 알아 두세요.

이렇게 고르세요 (풀이 요령)

"마지막 배치가 작을 때 epoch 평균 loss를 구하는 올바른 방법"은 각 배치 loss에 sample 수를 곱해 합산하고 전체 sample 수로 나눈다예요. "배치 loss를 단순 평균한다"는 오답이에요.

잠깐 확인 — 크기 4, 4, 2인 배치의 loss가 3, 6, 9일 때 epoch 평균 loss는?

(3×4 + 6×4 + 9×2) ÷ 10 = 5.4예요.

9-5. 샘플 시험 5번 손으로 풀기 ★★★

문제의 5줄은 위의 9-1과 같아요. 보기는 각 함수의 역할을 묻고 있어요.

optimizer.zero_grad() prediction = model(batch_x) loss = criterion(prediction, batch_y) loss.backward() optimizer.step()
보기내용판정이유
①optimizer.step()은 저장된 기울기를 이용해 옵티마이저에 전달된 파라미터를 갱신한다.맞음step의 정의 그대로예요. 계산된 .grad를 읽어 값을 고쳐요.
②loss.backward()는 기울기를 계산한 뒤 파라미터 값까지 갱신한다.틀림backward는 기울기만 계산·저장해요. 갱신은 step이에요(7장 실험에서 backward 직후 weight 1.0이 그대로였어요).
③optimizer.zero_grad()는 모델의 모든 파라미터 값을 0으로 만든다.틀림0으로 만드는(비우는) 대상은 기울기예요. 파라미터 값(weight)은 건드리지 않아요.
④criterion(prediction, batch_y)는 손실을 계산하고 이전 기울기를 초기화한다.틀림criterion은 loss 점수만 계산해요. 기울기 초기화는 zero_grad가 해요.
⑤optimizer.step()은 기울기를 새로 계산한 뒤 기존 기울기를 자동으로 제거한다.틀림step은 계산도 제거도 안 해요. 이미 저장된 기울기를 읽어 갱신만 해요.

정답은 ①번이에요. 교수님은 이 문제를 보여 주면서 수업 때 계속 얘기한 다섯 개 과정에 대한 설명 중 올바른 것을 고르는 문제라고 했고, 기울기를 초기화하는 일은 zero_grad가 한다고 말했어요. 시험에 이 모양 그대로 나오지는 않는다고 했지만 유형은 같아요.

외우기 팁

대상으로 구분하세요. zero_grad는 "기울기"를 비우고, backward는 "기울기"를 구하고, step은 "파라미터"를 바꾸고, criterion은 "loss"를 만들어요. 보기에서 함수와 대상이 어긋나면 틀린 문장이에요.

이렇게 고르세요 (풀이 요령)

① 보기마다 (함수, 하는 일, 대상)을 뽑아요. ② 위의 짝(zero_grad-기울기 비우기, backward-기울기 계산, step-파라미터 갱신, criterion-loss 계산)과 하나라도 다르면 지워요. ③ "A가 B도 같이 해 준다"는 보기(②, ④, ⑤처럼 한 함수가 두 가지 일을 한다고 말하는 것)는 거의 오답이에요. 각 함수는 한 가지 일만 해요.

잠깐 확인 — zero_grad() 없이 backward()를 2번 연속 하면 기울기는 어떻게 될까요?

두 번째 값이 첫 번째 값에 더해져서 2배 정도로 쌓여요. 학습에서는 매번 새 기울기만 필요해서 zero_grad로 지워야 해요.

9-6. 학습 데이터와 검증 데이터 — 참고 참고

이 절은 교수님 5주차 노트북의 학습 목표와 "오늘의 핵심 질문"에 나오는 내용이에요. 녹취에서 5주차 자료는 "반 정도만 준비했다"고 했고 시험 범위는 2~5주차이니, 코드까지 외우기보다 개념만 이해해 두세요.

한 줄 정의

train 데이터는 모델이 학습에 쓰는 데이터이고, validation(검증) 데이터는 학습에는 쓰지 않고 모델이 처음 보는 데이터에서도 잘 맞히는지 확인하려고 따로 떼어 둔 데이터예요.

비유 — 연습문제와 모의고사

연습문제로 공부하고, 한 번도 안 풀어 본 모의고사로 실력을 확인해요. 연습문제 답만 외웠다면 연습문제는 만점이어도 모의고사에서 점수가 떨어져요. 이렇게 학습 데이터에만 지나치게 맞춰진 상태를 과적합(overfitting)이라고 해요. (과적합은 교수님 자료에는 안 나오는 용어이고 참고용이에요.) 모의고사를 따로 두면 이것을 알아챌 수 있어요.

노트북의 핵심 질문을 풀이와 함께 정리하면 이래요.

핵심 질문답

모드 스위치는 두 개예요. model.train()은 학습 모드, model.eval()은 평가 모드예요. 층 중에는 학습할 때와 평가할 때 동작이 달라지는 것이 있어서 알려 주는 용도예요. 지금까지 쓴 nn.Linear와 ReLU는 둘 사이에 차이가 없어요. 교수님 4주차 슬라이드에도 학습이 끝난 모델로 예측할 때 이렇게 써요.

model.eval() with torch.no_grad(): y = model(torch.tensor([[5.0], [10.0]])) # 결과는 약 [[11.0], [21.0]]

평가 함수를 만들면 이런 모양이에요. 학습 5줄과 비교해서 보세요. 이 코드는 노트북의 학습 목표(evaluate())에 맞춰 제가 쓴 예시예요.

def evaluate(model, loader, criterion): model.eval() # 평가 모드 total_loss, total_samples = 0.0, 0 with torch.no_grad(): # 기울기 추적 끄기 for batch_x, batch_y in loader: prediction = model(batch_x) loss = criterion(prediction, batch_y) n = batch_x.size(0) total_loss += loss.item() * n total_samples += n return total_loss / total_samples

이렇게 고르세요 (풀이 요령)

평가 단계 설명에서는 "weight를 갱신하지 않는다. backward와 step을 쓰지 않고 loss만 계산한다"가 맞아요. model.eval()이 기울기 계산도 꺼 준다는 보기는 오답이에요. 그건 torch.no_grad()의 일이에요.

잠깐 확인 — 검증 데이터로 loss를 구한 뒤 loss.backward()와 optimizer.step()을 하면 왜 안 될까요?

검증 데이터가 학습에 쓰이는 셈이라서 "처음 보는 데이터에서의 성능"을 잴 수 없어요. 검증은 weight를 건드리지 않고 점수만 매겨야 해요.

이 장 3줄 요약
  • 한 배치 학습은 5줄이에요. zero_grad(기울기 지우기) → model(x)(예측) → criterion(loss) → backward(기울기 계산, 값은 그대로) → step(파라미터 갱신). 각 함수는 한 가지 일만 해요.
  • 이 5줄을 배치마다 실행하고(안쪽 for), 그것을 epoch만큼 반복해요(바깥 for). step 횟수는 배치 수 × epoch 수이고(90개, 20씩, 30 epoch이면 150번), epoch 평균 loss는 각 loss에 배치 sample 수를 곱해 더한 뒤 전체 sample 수로 나눠요.
  • (참고) 검증 데이터는 학습에 쓰지 않고 성능만 확인하는 데이터예요. 평가할 때는 model.eval()과 torch.no_grad()를 쓰고 backward·step은 하지 않아요. model.eval()만으로는 기울기 계산이 꺼지지 않아요.
