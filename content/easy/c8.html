Dataset과 DataLoader — 데이터를 배치로 나눠 꺼내기

지금까지는 데이터가 5개뿐이라 전부 한꺼번에 모델에 넣었어요. 실제 데이터는 수천, 수만 개라서 작은 묶음(배치)으로 나눠 넣어야 해요. 이 장에서는 데이터를 담는 Dataset, 배치로 묶어 주는 DataLoader, 그리고 "배치가 몇 개이고 마지막 배치는 몇 개인가"를 손으로 계산하는 방법을 배워요. 샘플 시험 4번이 바로 이 장이에요.

8-1. 용어 정리 — sample, batch, epoch, step ★★★

용어가 네 개 나와요. 처음에는 헷갈리니까 문제집으로 비유해 볼게요.

비유 — 문제집 풀기

문제집 한 권이 데이터 전체예요. 문제 하나(문제와 정답 쌍)가 sample, 한 번에 풀고 채점하는 묶음(예 20문제)이 batch, 채점할 때마다 공부 방법을 한 번 고치는 것이 step, 문제집을 처음부터 끝까지 한 바퀴 푸는 것이 epoch이에요.

용어뜻예시
sample입력 하나(여러 특성으로 이뤄짐)와 정답 하나이미지 1장과 그 라벨, 또는 x = [0, 1]과 y = 5
Datasetsample을 번호(인덱스)로 꺼낼 수 있는 데이터 모음dataset[0]
batch한 번에 처리하는 sample 묶음이미지 64장 묶음이면 크기 (64, 1, 28, 28)
step배치 하나로 학습하고 업데이트하는 과정 한 번학습 5단계 (zero_grad → forward → loss → backward → step) 1회
epoch학습 데이터 전체를 한 번 순회하는 것모든 배치를 한 번씩 학습

교수님은 이렇게 설명했어요. 데이터가 1000개이고 배치 크기가 20이면 20개씩 step을 거치니까 50번 하면 한 epoch이 돼요. 4주차 예제는 데이터 5개를 전부 한 번에 넣었기 때문에 한 epoch이 한 step이었어요. 앞으로는 배치로 나누니까 한 epoch에 여러 step이 있어요. 이렇게 데이터를 나눠 학습하는 방식을 미니 배치(mini-batch) 학습이라고 해요.

왜 나눠서 넣을까요? 데이터 천 개를 한 번에 넣으면 계산이 너무 많고 컴퓨터 메모리도 많이 필요해요. 그래서 20개, 30개씩 잘라서 넣어요.

이렇게 고르세요 (풀이 요령)

용어 문제는 단위로 구분하세요. sample = 데이터 1개, batch = sample 묶음, step = 배치 1개로 1번 업데이트, epoch = 전체 데이터 1바퀴예요. "한 epoch의 step 수 = 배치 개수"예요. 예를 들어 sample 10개, batch_size 4이면 한 epoch에 step이 3번이에요.

잠깐 확인 — 데이터 1000개를 배치 크기 20으로 학습하면 한 epoch에 step은 몇 번일까요?

50번이에요. 1000 ÷ 20 = 50개의 배치를 하나씩 학습해요.

8-2. Dataset — 입력과 정답을 한 쌍으로 묶은 명부 ★★

Dataset은 "번호를 말하면 그 번호의 (입력, 정답) 한 쌍을 꺼내 주는" 데이터 모음이에요. PyTorch의 torch.utils.data.Dataset 클래스를 상속해서 만들어요. 반드시 알아야 할 메서드가 세 개 있어요.

메서드역할이렇게 불려요
__init__(self, x, y)입력과 정답을 저장하고 개수가 같은지 확인MyDataset(x, y)로 만들 때
__len__(self)전체 sample 개수를 돌려줘요len(dataset)
__getitem__(self, index)해당 번호의 (입력, 정답) 쌍을 돌려줘요dataset[3]
비유

출석 번호가 붙은 명부예요. "3번 학생"이라고 말하면(dataset[3]) 그 학생의 정보를 꺼내 주고, "전체 몇 명?"이라고 물으면(len(dataset)) 인원수를 알려 줘요. 번호는 0번부터 시작해요.

dataset[3]이라고 쓰면 파이썬이 내부에서 dataset.__getitem__(3)을 호출해요. len(dataset)은 dataset.__len__()을 호출하고요. 앞 장에서 배운 "f(x)가 __call__을 부른다"와 같은 원리예요. 교수님이 직접 만든 코드를 볼게요.

class MyDataset(Dataset): def __init__(self, x, y): super().__init__() if len(x) != len(y): raise ValueError("입력과 정답의 sample 수가 달라요.") self.x = x self.y = y def __len__(self): return len(self.x) def __getitem__(self, index): return self.x[index], self.y[index] toy_x = torch.arange(10, dtype=torch.float32).reshape(-1, 1) toy_y = 2 * toy_x + 1 custom_dataset = MyDataset(toy_x, toy_y) print("sample 수:", len(custom_dataset)) x0, y0 = custom_dataset[0] print("첫 sample:", x0, y0) print("sample shape:", x0.shape, y0.shape)
sample 수: 10 첫 sample: tensor([0.]) tensor([1.]) sample shape: torch.Size([1]) torch.Size([1])
코드 줄무슨 뜻
class MyDataset(Dataset):Dataset을 물려받는 클래스를 만들어요.
super().__init__()부모 준비 작업이에요. 모델 때와 똑같아요.
if len(x) != len(y): raise ValueError입력과 정답 개수가 다르면 오류를 내요. 쌍이 안 맞으면 안 되니까요.
self.x = x, self.y = y데이터를 객체 안에 저장해요.
return len(self.x)sample 개수는 x의 길이예요.
return self.x[index], self.y[index]같은 번호의 입력과 정답을 짝지어 돌려줘요.
toy_y = 2 * toy_x + 1정답 y = 2x + 1. x = 0이면 y = 1, x = 3이면 y = 7이에요.
custom_dataset[0]0번 sample (x = [0.], y = [1.])을 돌려줘요. 각각 크기가 (1,)예요.

교수님은 직접 만들 수도 있지만 이미 만들어진 TensorDataset을 쓰면 된다고 했어요. 시험에서는 직접 만드는 코드보다 __len__과 __getitem__이 각각 무슨 일을 하는지를 이해하는 게 중요해요.

이렇게 고르세요 (풀이 요령)

Dataset 설명 보기에서 맞는 것은 "__len__은 전체 sample 수를, __getitem__(index)는 해당 번호의 (입력, 정답) 쌍을 돌려준다"예요. dataset[3]은 네 번째 sample이에요(0번부터 세요).

잠깐 확인 — dataset[3]을 쓰면 내부에서 어떤 메서드가 호출될까요?

__getitem__(3)이에요. 3번 인덱스(네 번째) sample의 (입력, 정답) 쌍이 나와요.

8-3. TensorDataset — 이미 만들어진 Dataset ★★★

TensorDataset은 입력 Tensor와 정답 Tensor를 넘기면 위의 일을 대신해 주는 PyTorch 기본 도구예요. Dataset을 상속해서 만들어져 있어요. 넘기는 Tensor들은 첫 번째 차원(sample 수)이 같아야 해요.

교수님이 시험 샘플과 같은 데이터로 설명했어요. x는 0부터 19까지를 (10, 2) 모양으로 만들고, y는 x의 첫 칸 + 2 × x의 둘째 칸 + 3으로 만들어요.

toy_x = torch.arange(20, dtype=torch.float32).reshape(10, 2) toy_y = toy_x[:, 0:1] * 1 + toy_x[:, 1:2] * 2 + 3 dataset = TensorDataset(toy_x, toy_y) print("sample 수:", len(dataset)) x0, y0 = dataset[0] print("첫 sample:", x0, y0) print("sample shape:", x0.shape, y0.shape)
sample 수: 10 첫 sample: tensor([0., 1.]) tensor([5.]) sample shape: torch.Size([2]) torch.Size([1])
코드 줄무슨 뜻
torch.arange(20).reshape(10, 2)0~19를 10줄 × 2칸으로 놓아요. [[0, 1], [2, 3], ..., [18, 19]]. sample 10개, 특성 2개예요.
toy_x[:, 0:1]모든 줄의 첫 번째 칸을 (10, 1) 모양으로 꺼내요.
toy_y = 첫째 + 2 × 둘째 + 3정답 y. 크기는 (10, 1)이에요.
TensorDataset(toy_x, toy_y)x와 y를 같은 번호끼리 짝지어 Dataset으로 만들어요.
len(dataset)10이에요. 숫자 20개가 아니라 줄(sample) 수예요.
dataset[0]첫 sample. x는 [0., 1.](크기 (2,)), y는 [5.](크기 (1,))예요. 0 + 2×1 + 3 = 5.

y값을 손으로 한 번에 구하는 요령이 있어요. i번째 sample(0부터 센)의 x는 [2i, 2i+1]이니까 y = 2i + 2(2i+1) + 3 = 6i + 5예요.

외우기 팁

len(dataset)은 sample 수이고 Tensor 안의 숫자 전체 개수가 아니에요. x가 (10, 2)이면 숫자는 20개지만 sample은 10개라서 답은 10이에요. 교수님이 dataset[0]이 (입력, 정답) 한 쌍이라는 점을 강조했어요.

이렇게 고르세요 (풀이 요령)

x = torch.arange(20).reshape(10, 2)를 TensorDataset에 넣으면 len(dataset)은 10이에요. "20"이 들어 있는 보기는 오답이에요. sample 하나의 x 크기는 (2,), y 크기는 (1,)이에요.

잠깐 확인 — x가 (100, 5) 크기이면 TensorDataset의 len은? sample 하나의 x 크기는?

len은 100이고, sample 하나의 x 크기는 (5,)예요. 첫 번째 숫자가 sample 수이고 나머지가 한 sample의 모양이에요.

8-4. DataLoader — sample을 모아서 배치로 만들어 주는 도구 ★★★

DataLoader는 Dataset에서 sample을 꺼내 지정한 크기의 배치로 묶어서 하나씩 건네주는 도구예요. 교수님이 먼저 for 문으로 직접 sample을 모아 torch.stack으로 쌓아 보여 준 뒤, "이 일을 DataLoader가 대신 해 주니 걱정할 필요 없다"고 했어요.

비유 — 급식 배식

학생(sample)이 줄을 서 있고, 배식 담당(DataLoader)이 4명씩 묶어서 식당으로 들여보내요. 마지막에 2명이 남으면 그 2명이 마지막 묶음이 되고요. 줄을 매번 새로 섞을지(shuffle)도 담당이 정해요.

옵션역할기본값
batch_size한 배치에 넣을 sample 수1
shuffle순회할 때마다 sample 순서를 섞을지False
drop_last배치 크기보다 모자란 마지막 배치를 버릴지False
from torch.utils.data import TensorDataset, DataLoader loader = DataLoader( dataset, batch_size=4, shuffle=False, drop_last=False ) print("dataset 길이:", len(dataset), "loader 길이:", len(loader)) for i, (batch_x, batch_y) in enumerate(loader): print(i, tuple(batch_x.shape), tuple(batch_y.shape), batch_y.flatten().tolist())
dataset 길이: 10 loader 길이: 3 0 (4, 2) (4, 1) [5.0, 11.0, 17.0, 23.0] 1 (4, 2) (4, 1) [29.0, 35.0, 41.0, 47.0] 2 (2, 2) (2, 1) [53.0, 59.0]
코드 줄무슨 뜻
DataLoader(dataset, batch_size=4, ...)dataset에서 4개씩 묶어서 꺼내 주는 도구를 만들어요.
len(dataset)sample 수 = 10
len(loader)배치 수 = 3 (4개, 4개, 2개)
for batch_x, batch_y in loader:배치를 하나씩 꺼내요. 한 번 꺼낼 때마다 입력 묶음과 정답 묶음이 짝으로 나와요.
enumerate(loader)번호 i를 0, 1, 2로 같이 붙여 줘요.
tuple(batch_x.shape)배치의 입력 크기예요. (4, 2)는 sample 4개, 특성 2개예요.
batch_y.flatten().tolist()(4, 1) 모양의 정답을 일렬로 펴서 파이썬 리스트로 바꿔요.

마지막 배치의 x는 [[16, 17], [18, 19]]이에요. 이 for 문을 끝까지 한 번 돌면 전체 데이터를 한 바퀴 돈 것이라서 1 epoch이에요.

교수님이 던진 질문도 정리해 볼게요. "dataset[0]과 next(iter(loader))는 무엇이 다른가요?"

구분무엇이 나오나x, y 크기
dataset[0]sample 하나(2,) , (1,)
next(iter(loader))첫 번째 배치(sample 4개 묶음)(4, 2) , (4, 1)

배치의 크기는 맨 앞에 배치 크기가 붙는 모양이에요. sample 하나의 (2,)가 4개 쌓이면 (4, 2)가 돼요. 이것이 5장에서 모델에 넣던 "배치 4개, 특성 2개" 입력이에요.

이렇게 고르세요 (풀이 요령)

len(dataset)은 sample 수, len(loader)는 배치 수예요. 둘을 섞어 쓴 보기(예 "10 10")는 오답이에요. batch_size=4이면 한 배치 x의 크기는 (4, 특성 수)이고 마지막 배치만 작을 수 있어요.

잠깐 확인 — DataLoader를 for 문으로 한 번 끝까지 돌면 무엇이 한 번 끝난 건가요?

1 epoch이에요. 모든 sample을 한 번씩 사용했으니까요. 이때 for 문이 도는 횟수는 배치 수(len(loader))와 같아요.

8-5. 배치 개수와 마지막 배치 크기 계산 ★★★

샘플 시험 4번의 핵심이에요. 규칙은 두 가지뿐이에요.

배치 개수 공식

drop_last=False(기본)이면 배치 수 = 올림(sample 수 ÷ batch_size)이고, 마지막 배치는 남은 만큼(나머지)만 들어요. 나머지가 없으면 마지막도 꽉 차요.

drop_last=True이면 배치 수 = 내림이고 모자란 마지막 배치는 버려요.

예를 들어 10 ÷ 4 = 2.5이니까 올림하면 3개예요. 4개 + 4개 + (10 − 8 = 2개)로 나뉘어요. 교수님 노트북과 제가 실행한 결과를 표로 모았어요.

sample 수batch_sizedrop_last배치 수각 배치 크기
103False4[3, 3, 3, 1]
104False3[4, 4, 2]
106False2[6, 4]
104True2[4, 4] (마지막 2개 버림)
9020False5[20, 20, 20, 20, 10]
9020True4[20, 20, 20, 20]
100020False5020이 50번
10032False4[32, 32, 32, 4]

마지막 배치를 구하는 요령은 이래요. 반복문이 끝난 뒤의 batch_x, batch_y는 마지막으로 꺼낸 배치예요. 파이썬에서 for 문 변수는 반복이 끝나도 마지막 값이 남아 있기 때문이에요. drop_last=False이면 마지막 배치는 맨 끝 sample들이고, drop_last=True이면 버려진 것을 뺀 마지막 꽉 찬 배치예요.

  • drop_last=False, batch_size=4 → 마지막 배치는 8번, 9번 sample → y = [53.0, 59.0]
  • drop_last=True, batch_size=4 → 마지막 배치는 4~7번 sample → y = [29.0, 35.0, 41.0, 47.0]
외우기 팁

배치 수는 "올림"이에요(drop_last를 안 쓰면). 10 ÷ 4 = 2.5 → 3. 90 ÷ 20 = 4.5 → 5. 마지막 크기는 나머지예요. 10을 4로 나눈 나머지 2, 90을 20으로 나눈 나머지 10이에요. 나머지가 0이면 마지막도 꽉 차요.

이렇게 고르세요 (풀이 요령)

① 배치 수는 올림(drop_last=True면 내림)으로 계산해요. ② 배치 크기 목록은 batch_size를 반복하다가 마지막에 나머지를 적어요. ③ 마지막 배치 값은 맨 뒤 sample을 직접 계산해요. 그리고 문제 코드에서 shuffle=False인지도 확인하세요. True이면 마지막 배치에 어떤 sample이 들어갈지 매번 달라져서 값을 하나로 정할 수 없어요.

잠깐 확인 — sample 100개, batch_size 32, drop_last=False이면 배치 수와 마지막 배치 크기는?

배치 수는 올림(100 ÷ 32 = 3.125) = 4이고, 마지막 크기는 100 − 32×3 = 4예요. [32, 32, 32, 4]예요.

8-6. shuffle — 매 epoch마다 섞기 ★★

shuffle=True를 주면 순회를 시작할 때마다 sample 순서를 새로 섞어요. 그러면 같은 데이터라도 epoch마다 배치 구성이 달라져요. 교수님이 같은 sample이 매번 같은 묶음으로만 들어가면 곤란하니까, 매번 섞으면 여러 상황을 고려해서 학습되는 효과가 있다고 설명했어요.

비유 — 카드 섞기

카드 놀이를 할 때 한 판이 끝나면 카드를 새로 섞고 나눠 줘요. 카드의 앞면(x)과 뒷면(y)은 붙어 있어서 짝은 그대로 같이 움직여요. 그리고 섞었다고 카드가 사라지지는 않아요. 한 epoch이 끝나면 모든 카드가 한 번씩 쓰인 거예요.

교수님 노트북에서 shuffle=True로 돌린 첫 배치는 이렇게 나왔어요. 실행할 때마다 달라요.

x = [[ 2, 3], [18, 19], [ 4, 5], [10, 11]] y = [ 11, 59, 17, 35 ]

x의 순서는 뒤섞였지만 짝이 되는 y(11, 59, 17, 35)는 8-3 표의 값과 정확히 맞아요. 배치 수와 크기는 shuffle과 상관없이 [4, 4, 2]로 그대로예요.

"학습에는 shuffle=True, 검증에는 shuffle=False"가 교수님이 노트북에 질문으로 적어 둔 내용이에요. 이유는 9장에서 다뤄요. 평가는 순서를 섞을 필요가 없고, 결과를 매번 같은 순서로 비교하기 쉽게 하려는 거예요.

이렇게 고르세요 (풀이 요령)

"shuffle=True의 효과"는 매 순회마다 sample 순서가 달라진다(입력과 정답의 짝은 유지)예요. "일부 데이터가 빠진다"거나 "배치 크기가 바뀐다"는 보기는 오답이에요.

잠깐 확인 — shuffle=True이면 한 epoch에 일부 sample이 빠질 수 있을까요?

아니에요. 순서만 섞이고 모든 sample이 한 번씩 사용돼요. 빠지는 경우는 drop_last=True로 모자란 마지막 배치를 버릴 때뿐이에요.

8-7. 샘플 시험 4번 손으로 풀기 ★★★

이제 문제를 풀 준비가 됐어요. 코드는 이래요.

x = torch.arange(20, dtype=torch.float32).reshape(10, 2) y = x[:, 0:1] + 2 * x[:, 1:2] + 3 dataset = TensorDataset(x, y) loader = DataLoader(dataset, batch_size=4, shuffle=False, drop_last=False) batch_sizes = [] for batch_x, batch_y in loader: batch_sizes.append(len(batch_x)) print(len(dataset), len(loader)) print(batch_sizes) print(batch_y.flatten().tolist())

세 줄의 출력을 차례로 구해요.

  1. 첫 번째 출력 len(dataset), len(loader) — x가 (10, 2)이니 sample은 10개예요. 배치는 올림(10 ÷ 4) = 3개예요. 출력은 10 3이에요.
  2. 두 번째 출력 batch_sizes — 반복할 때마다 그 배치의 sample 수를 리스트에 넣어요. 4, 4, 2이니 [4, 4, 2]예요.
  3. 세 번째 출력 batch_y — 반복문이 끝난 뒤의 값이라 마지막 배치예요. 마지막 배치는 8번, 9번 sample이에요. x가 [16, 17]이면 y = 16 + 2×17 + 3 = 53, x가 [18, 19]이면 y = 18 + 2×19 + 3 = 59예요. 출력은 [53.0, 59.0]이에요.

이 세 조건을 모두 만족하는 보기는 ③ 10 3 / [4, 4, 2] / [53.0, 59.0]이에요. 오답 보기들이 어떤 실수를 노렸는지도 볼게요.

보기내용왜 틀렸나
①10 2 / [4, 4] / [29, 35, 41, 47]drop_last=True일 때의 답이에요. 문제는 False라서 마지막 2개를 버리지 않아요.
②10 3 / [4, 4, 4] / [53, 59, 65, 71]마지막 배치가 4개로 가득 찼다고 착각했어요. 10개밖에 없는데 65, 71은 없는 sample이에요.
④20 5 / [4, 4, 4, 4, 4] / [53, 59]sample 수를 숫자 개수(20)로 셌어요. 20 ÷ 4 = 5로 이어진 오답이에요.
⑤10 3 / [4, 4, 2] / [16, 18]y 대신 x의 첫 칸 값(16, 18)을 적었어요. 정답은 y예요.
이렇게 고르세요 (풀이 요령)

세 줄 출력 문제는 한 줄씩 지우는 방식으로 풀어요. ① len(dataset)은 sample 수, len(loader)는 배치 수라서 "10 3" 외의 첫 줄을 먼저 지워요. ② 두 번째 줄에서 합이 10이 안 되는 보기를 지워요([4, 4, 4]는 12). ③ 마지막 줄은 마지막 배치의 y를 직접 계산해서 맞는 것을 골라요. 이 문제는 10 3 → [4, 4, 2] → [53.0, 59.0]이에요.

잠깐 확인 — 같은 코드에서 drop_last=True로 바꾸면 세 줄 출력은?

10 2, [4, 4], [29.0, 35.0, 41.0, 47.0]이에요. 배치 수는 내림(2), 마지막 배치는 4~7번 sample이라서 y는 6i+5에 4~7을 넣은 값이에요.

이 장 3줄 요약
  • sample은 (입력, 정답) 한 쌍, batch는 sample 묶음, step은 배치 1개 학습, epoch은 데이터 전체 1바퀴예요. Dataset은 __len__(sample 수)과 __getitem__(번호로 한 쌍 꺼내기)을 가지고, TensorDataset(x, y)의 길이는 x의 첫 번째 차원이에요(예 (10, 2)이면 10).
  • DataLoader(dataset, batch_size, shuffle, drop_last)는 sample을 배치로 묶어 줘요. len(loader)는 배치 수(올림, drop_last=True면 내림)이고, 마지막 배치는 나머지만큼 작아요. 10개를 4로 나누면 [4, 4, 2]예요.
  • shuffle=True는 순회마다 순서를 섞되 x, y 짝은 유지해요(학습은 True, 검증은 False). 반복문이 끝난 뒤 batch_y는 마지막 배치이고, 이 문제의 정답은 10 3 / [4, 4, 2] / [53.0, 59.0]이에요.
