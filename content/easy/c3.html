GPU와 Colab — 계산을 빠르게 해 주는 장치

딥러닝은 계산이 아주 많아서 GPU라는 장치를 쓰면 훨씬 빨라져요. 이 장에서는 GPU가 왜 빠른지, 코드에서 어떻게 GPU를 고르고 데이터를 옮기는지, 내 컴퓨터에 GPU가 없을 때 Colab으로 빌려 쓰는 방법을 배워요. 시험에서는 "device가 다르면 계산이 안 된다"와 ".to(device)는 다시 저장해야 한다"가 핵심이에요.

3-1. GPU는 왜 빠를까 — CPU와 GPU의 차이 ★★

컴퓨터의 계산 장치는 두 종류예요. CPU는 컴퓨터의 두뇌이고, GPU는 원래 그래픽(화면) 처리를 하던 장치예요. 둘 다 계산을 하지만 잘하는 일이 달라요.

장치강점
CPU복잡하고 다양한 작업을 순차적으로 처리하는 데 강해요
GPU많은 단순 연산을 병렬로(동시에) 처리하는 데 강해요. 대량의 행렬 연산에 유리해요
비유 — 주방장 한 명 vs 알바생 수천 명

CPU는 복잡한 코스 요리를 차례차례 완성하는 숙련된 주방장 한 명이에요. GPU는 감자 깎기, 곱셈 같은 단순한 일을 알바생 수천 명이 동시에 하는 것과 같아요. 감자 1만 개를 깎아야 한다면 주방장 한 명보다 알바생 수천 명이 훨씬 빨라요.

왜 딥러닝에 GPU를 쓸까요? 딥러닝은 숫자를 곱하고 더하는 단순한 계산을 어마어마하게 반복하기 때문이에요(예측과 기울기 계산이 모두 그래요). 단순 계산이 많을수록 GPU가 유리해요. 교수님도 "순전파와 역전파가 단순 연산의 반복이라 GPU가 유리하다"고 설명했어요.

시험엔 이렇게 써요 — 이렇게 고르세요

CPU는 복잡하고 다양한 작업을 순차적으로 처리하는 데 강하고, GPU는 많은 단순 연산을 병렬로 처리하는 데 강하다. 딥러닝은 대량의 행렬 연산이 많아 GPU를 사용하면 학습 속도가 크게 향상된다. 선택지에서 두 장치의 특징이 서로 바뀌어 있으면 오답이에요.

잠깐 확인 — 단순한 곱셈을 엄청나게 많이 반복해야 할 때 CPU와 GPU 중 어느 쪽이 유리한가요?

GPU예요. 단순한 연산을 동시에 많이 처리하는 것이 GPU의 장점이에요.

3-2. 내 컴퓨터에 GPU가 있나 — cuda와 is_available ★★

GPU는 컴퓨터에 따라 있기도 하고 없기도 해요. 특히 노트북에는 없는 경우가 많아요. PyTorch에서 GPU를 쓰려면 NVIDIA 그래픽 카드와 CUDA(쿠다)가 필요해요. 교수님 설명으로 CUDA는 "GPU를 사용할 수 있게 해 주는 프로그램"이에요. 컴퓨터에 GPU가 있는지는 터미널에서 nvidia-smi를 입력해 확인해요. 결과가 나오면 GPU가 있는 거예요.

이 수업은 1주차에 GPU 유무와 관계없이 CPU 버전 PyTorch로 통일하기로 했어요. GPU판은 용량이 3~4GB로 커서 설치가 오래 걸리고 충돌도 생기기 때문이에요. 교수님은 GPU가 필요하면 학과 서버를 쓸 계획이라고 했어요.

코드에서는 이렇게 GPU 사용 가능 여부를 물어봐요.

print("CUDA 사용 가능 여부:", torch.cuda.is_available()) device = 'cuda' if torch.cuda.is_available() else 'cpu' print("선택된 device:", device)
CUDA 사용 가능 여부: False 선택된 device: cpu
코드 줄무슨 뜻
torch.cuda.is_available()"지금 GPU를 쓸 수 있나요?"라는 질문. 가능하면 True, 아니면 False
'cuda' if ... else 'cpu'0장에서 본 한 줄 조건식이에요. 쓸 수 있으면 'cuda'(GPU), 아니면 'cpu'를 device 이름으로 골라요
위 결과위 출력은 GPU가 없는 컴퓨터에서 나온 결과예요. GPU가 있는 곳(예: Colab GPU)에서는 True와 cuda가 나와요
왜 'cuda'라고 고정하지 않고 이렇게 쓸까요

코드가 돌아갈 컴퓨터에 GPU가 있는지 미리 알 수 없기 때문이에요. 'cuda'로 못 박으면 GPU가 없는 PC에서 에러가 나요. 위 한 줄로 "있으면 GPU, 없으면 CPU"를 고르면 같은 코드를 어디서든 그대로 돌릴 수 있어요. 교수님도 "디바이스를 명시하는 건 좋지 않다"고 했어요.

한 가지 더 알아 둘 것이 있어요. CUDA를 설치했다고 is_available()이 저절로 True가 되는 것은 아니에요. 실제로 사용할 수 있는 GPU가 있는 환경이어야 True가 나와요.

시험엔 이렇게 써요 — 이렇게 고르세요

GPU 사용 가능 여부는 torch.cuda.is_available()로 확인하고, device = 'cuda' if torch.cuda.is_available() else 'cpu'로 선택하면 GPU 유무와 관계없이 같은 코드를 실행할 수 있다. 결과 예측 문제는 GPU가 없는 환경이면 False와 cpu가 나온다고 보세요.

잠깐 확인 — 노트북에 GPU가 없을 때 위 코드의 device는 무엇이 되나요?

'cpu'예요. is_available()이 False라서 else 쪽 값을 골라요.

3-3. Tensor와 모델을 device로 옮기기 — .to(device) ★★★

Tensor는 처음 만들면 CPU에 생겨요. 어느 장치에 있는지는 x.device로 봐요. GPU로 보내려면 두 가지 방법이 있어요.

  • 만들 때부터 지정 — torch.zeros(2, 3, device=device)
  • 만든 뒤에 옮기기 — x = x.to(device)
device = 'cuda' if torch.cuda.is_available() else 'cpu' x = torch.zeros(2, 3, device=device) y = torch.randn(3, 4) print(y.device) y = y.to(device) print(y.device)
코드 줄GPU 없는 컴퓨터GPU 있는 환경 (예 Colab)
print(y.device) (처음)cpucpu (처음은 항상 CPU)
y = y.to(device) 뒤 print(y.device)cpu (옮길 곳이 CPU)cuda:0 (0번 GPU로 이동)

"cuda:0"의 0은 0번 GPU라는 뜻이에요. GPU가 한 장이면 그냥 0번이에요.

제일 중요한 규칙

.to(device)는 원본을 바꾸지 않고 "옮겨진 새 Tensor"를 돌려줘요. 그래서 반드시 x = x.to(device)처럼 변수에 다시 저장해야 해요. x.to(device)만 쓰고 저장하지 않으면 x는 그대로 CPU에 있어요.

비유 — 택배

택배(.to)를 보내면 상품이 "새로 도착한 택배 상자"로 와요. 그 상자를 받아서 선반(변수 x)에 올려놓아야 써먹을 수 있어요. 받지 않고 흘려보내면 선반에는 원래 물건만 있어요.

모델(layer)도 같은 방법으로 옮겨요.

from torch import nn model = nn.Linear(4, 2) model = model.to(device) x = torch.randn(3, 4).to(device) y = model(x) print(y.device) print(model.weight.device)
cpu cpu
코드 줄무슨 뜻
model = nn.Linear(4, 2)입력 4개, 출력 2개인 한 층짜리 모델
model = model.to(device)모델의 weight, bias를 device로 옮겨요(수업 슬라이드의 방식 그대로)
torch.randn(3, 4).to(device)(3, 4) 입력을 만들자마자 같은 device로 옮겨요. 한 줄에 붙여 쓴 모양이에요
y = model(x)모델과 입력이 같은 곳에 있으니 계산돼요. 결과도 같은 device에 생겨요
출력 cpu, cpuGPU 없는 컴퓨터의 결과예요. GPU 환경이면 cuda:0, cuda:0이 나와요
시험엔 이렇게 써요 — 이렇게 고르세요

.to(device)는 새 Tensor를 반환하므로 x = x.to(device)처럼 반환값을 변수에 다시 저장해야 한다. 모델도 model = model.to(device)로 옮긴다. 선택지에 "x.to(device)만 실행해도 x가 GPU로 이동한다"가 있으면 오답이에요.

잠깐 확인 — GPU가 있는 환경에서 x = torch.randn(3, 4)를 만든 뒤 x.to('cuda')를 저장 없이 한 줄만 실행했습니다. 이어서 print(x.device)를 하면?

cpu예요. 옮겨진 새 Tensor를 변수에 저장하지 않아서 x는 그대로 CPU에 있어요.

3-4. 같은 device에 있어야 계산돼요 ★★★

연산에 참여하는 모든 Tensor와 모델은 같은 device에 있어야 해요. CPU의 Tensor와 GPU의 Tensor를 더하거나 곱하면 "device가 다르다"는 RuntimeError가 나요.

비유 — 집 냉장고와 식당 주방

한 재료는 집 냉장고에, 다른 재료는 식당 주방에 있다면 한 요리로 합칠 수 없어요. 한쪽으로 옮겨 와야 해요. CPU 메모리와 GPU 메모리는 따로 분리되어 있어서(교수님 설명) 서로 다른 곳에 있는 Tensor끼리는 바로 계산할 수 없어요.

상황결과고치는 법
CPU Tensor + GPU Tensordevice가 달라서 에러한쪽을 x = x.to(device)로 같은 곳에 옮기기
GPU의 모델에 CPU 입력을 넣기에러입력도 .to(device)
CPU의 모델에 GPU 입력을 넣기에러모델도 .to(device)

그래서 실제 학습 코드는 보통 아래 순서를 따라요. 모델을 device에 올리고, 데이터를 꺼낼 때마다 batch도 같은 device로 보내요.

device = 'cuda' if torch.cuda.is_available() else 'cpu' model = model.to(device) for batch_x, batch_y in loader: batch_x = batch_x.to(device) batch_y = batch_y.to(device) prediction = model(batch_x)
코드 줄무슨 뜻
model = model.to(device)학습 시작 전에 모델을 한 번만 옮겨요
for batch_x, batch_y in loader:데이터를 batch 단위로 꺼내요(0장에서 본 짝 받기)
batch_x = batch_x.to(device)꺼낸 입력을 모델과 같은 device로. 다시 저장해야 해요
batch_y = batch_y.to(device)정답도 같은 곳으로. 나중에 loss를 계산할 때 필요해요
시험엔 이렇게 써요 — 이렇게 고르세요

연산에 참여하는 모든 Tensor는 같은 device에 있어야 하며 모델과 입력도 마찬가지이다. device가 다르면 연산할 수 없다. 오류가 나면 "shape, dtype, device" 순서로 확인하라는 교수님의 말씀을 떠올리세요.

잠깐 확인 — 모델은 GPU로 보냈는데 입력 x는 CPU 그대로 넣었습니다. 어떻게 되나요?

device가 달라서 에러가 나요. x = x.to(device)로 입력도 GPU로 보내야 해요.

3-5. GPU Tensor를 NumPy로 바꾸기

NumPy 배열은 CPU 메모리에만 있어요. GPU에 있는 Tensor를 바로 NumPy로 바꿀 수 없고, 먼저 CPU로 옮긴 뒤 바꿔요. 기울기를 추적 중인 Tensor(requires_grad=True)는 detach()로 추적을 끊고 바꿔요(Autograd 장에서 배워요).

목적방법
CPU → GPUx = x.to('cuda')
GPU → CPUx = x.to('cpu')
GPU Tensor → NumPyx.to('cpu').numpy() (CPU로 먼저)
기울기 추적 중인 Tensor → NumPyx.detach().to('cpu').numpy()
t = torch.randn(3, requires_grad=True) print(t.detach().to('cpu').numpy().shape)
(3,)

기울기를 추적하는 Tensor에 detach() 없이 .numpy()를 하면 "requires grad인 Tensor에는 numpy()를 쓸 수 없고 detach().numpy()를 쓰라"는 에러가 나요.

시험엔 이렇게 써요 — 이렇게 고르세요

NumPy 배열은 CPU 메모리에만 저장되므로 GPU Tensor는 .to('cpu').numpy()로 CPU로 옮긴 뒤 변환한다. requires_grad=True인 Tensor는 detach()로 계산 그래프에서 분리한 뒤 변환한다. 순서는 "(필요하면 detach) → CPU → numpy"예요.

잠깐 확인 — GPU에 있는 Tensor g를 NumPy로 바꾸는 올바른 한 줄은?

g.to('cpu').numpy()예요. CPU로 먼저 옮겨야 해요.

3-6. 내 컴퓨터에 GPU가 없다면 — Google Colab에서 GPU 켜기 ★

Colab(코랩)은 구글이 인터넷으로 빌려주는 컴퓨터예요. 웹 브라우저로 접속해서 코드를 실행하고, 무료로 GPU도 써 볼 수 있어요. 내 컴퓨터에 GPU가 없어도 돼요. 교수님은 1주차에 "GPU가 없는 학생은 Colab 계정을 만들어 보라"고 했어요.

비유 — 고성능 PC방

3-7. 종합 — 코드 읽기 연습 ★★

배운 것을 한꺼번에 써서 아래 코드의 결과를 따라가 보세요. GPU가 없는 컴퓨터에서 실행했다고 가정해요.

device = 'cuda' if torch.cuda.is_available() else 'cpu' a = torch.ones(2, 3) b = torch.ones(2, 3, device=device) a.to(device) c = a + b print(a.device) print(c.shape)
cpu torch.Size([2, 3])
코드 줄무슨 뜻
device = ...GPU가 없으니 'cpu'
a = torch.ones(2, 3)(2, 3) 크기의 1로 찬 Tensor. 기본 위치는 CPU
b = torch.ones(2, 3, device=device)device가 cpu라서 b도 CPU에 생겨요
a.to(device)다시 저장하지 않아서 a에는 변화가 없어요(어차피 옮길 곳도 CPU)
c = a + b둘 다 CPU에 있고 shape이 같아서 계산돼요. 모든 값이 2
print(a.device)cpu
print(c.shape)torch.Size([2, 3])

같은 코드를 GPU 있는 환경(Colab)에서 실행하면 달라져요. device가 'cuda'가 되어 b는 GPU에 생기고, a.to(device)는 저장하지 않아 a는 CPU에 남아요. 그러면 a + b에서 device가 달라 에러가 나요. 같은 코드인데 환경에 따라 결과가 갈리는 대표적인 예예요.

코드에 .to(device)가 보이면 먼저 "다시 저장했는가?"를 확인하세요. 저장하지 않았으면 Tensor는 원래 자리에 그대로예요. 그다음 "계산에 참여하는 Tensor가 전부 같은 device인가?"를 확인하면 돼요.

잠깐 확인 — x = x.to(device) 대신 x.to(device)만 썼을 때 생기는 문제를 한 문장으로 말해 보세요.

.to()는 이동한 새 Tensor를 돌려줄 뿐 원본을 바꾸지 않아서, 저장하지 않으면 x는 계속 원래 device에 남아요.

이 장 3줄 요약
  • CPU는 복잡한 일을 순차적으로, GPU는 단순한 일을 병렬로 잘해서 행렬 계산이 많은 딥러닝에는 GPU가 유리해요.
  • device = 'cuda' if torch.cuda.is_available() else 'cpu'로 장치를 고르고, x = x.to(device)처럼 반드시 다시 저장해요. 모델과 입력은 같은 device에 있어야 해요.
  • GPU Tensor는 .to('cpu').numpy()로 NumPy로 바꾸고, GPU가 없으면 Colab에서 런타임 → 런타임 유형 변경 → T4 GPU → 저장으로 켜요.
