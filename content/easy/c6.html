Autograd — 기울기를 자동으로 구해 주는 기능

모델이 학습한다는 것은 "틀린 정도(loss)를 줄이는 방향으로 숫자를 조금씩 고치는 일"이에요. 그 방향을 알려 주는 것이 기울기(gradient)이고, PyTorch가 이것을 자동으로 계산해 주는 기능이 Autograd예요. 이 장에서는 requires_grad, backward(), .grad, 기울기가 쌓이는 성질, torch.no_grad()를 배워요.

6-1. 왜 기울기가 필요할까 — 방향과 민감도

모델에는 W와 B 같은 숫자(파라미터)가 있어요. 처음에는 아무 값이나 넣어 두기 때문에 예측이 많이 틀려요. 이 틀린 정도를 숫자 하나로 나타낸 것이 손실(loss)이에요. 우리 목표는 loss가 작아지도록 파라미터를 고치는 거예요.

한 줄 정의

기울기(gradient) = 파라미터를 살짝 바꿨을 때 loss가 얼마나, 어느 방향으로 변하는지를 알려 주는 숫자예요. 부호는 방향, 크기는 민감도예요.

비유 — 안개 낀 산에서 내려오기

안개가 짙은 산에서 가장 낮은 곳으로 내려가려면 발밑의 경사를 느껴서 "내리막 쪽"으로 한 걸음 가면 돼요. 기울기가 바로 그 발밑의 경사예요. 경사가 가파를수록(크기가 클수록) loss가 그 방향에 더 민감하다는 뜻이에요.

업데이트 식은 이렇게 써요. 학습률(learning rate, η)은 "한 걸음의 크기"예요. 7장에서 자세히 배워요.

w ← w − η × (loss를 w로 미분한 기울기)

예를 들어 loss가 L = w²이고 w = 3이면 기울기는 2w = 6이에요. 학습률이 0.1이면 w = 3 − 0.1 × 6 = 2.4가 돼요. loss는 3² = 9에서 2.4² = 5.76으로 줄었어요. 기울기가 양수라서 w를 줄인 거예요. 반대로 기울기가 음수면 w를 늘려요.

기울기뜻업데이트
양수 (+)w가 커지면 loss도 커져요w를 줄여요
음수 (−)w가 커지면 loss가 줄어요w를 늘려요
크기가 큼loss가 w에 민감해요많이 움직여요
이렇게 고르세요 (풀이 요령)

기울기를 설명하는 보기에서는 "파라미터를 바꿨을 때 loss가 변하는 방향과 정도"가 맞는 문장이에요. 업데이트는 기울기의 반대 방향으로 해서 loss를 줄이니, "기울기 방향으로 더한다"는 보기는 오답이에요. 식은 w ← w − 학습률 × 기울기예요.

잠깐 확인 — 기울기가 −24이고 학습률이 0.01이면 w는 커질까요, 작아질까요?

커져요. w − 0.01 × (−24) = w + 0.24이니까 0.24만큼 커져요. 기울기가 음수이면 w를 늘려요.

6-2. requires_grad, backward(), .grad — 가장 기본 예제 ★★★

PyTorch에게 "이 값의 기울기가 필요해"라고 알려 주는 표시가 requires_grad=True예요. 이 표시가 붙은 Tensor에서 시작한 계산은 PyTorch가 전부 기록해 두었다가, 나중에 기울기를 한꺼번에 계산해요.

  • requires_grad=True : "이 값부터 계산 과정을 기록해 줘."
  • L.backward() : 마지막 결과 L에서 거꾸로 거슬러 가며 기울기를 계산해서 저장해요.
  • w.grad : 저장된 기울기를 꺼내 보는 곳이에요. backward 전에는 None(아직 없음)이에요.
w = torch.tensor(3.0, requires_grad=True) L = w ** 2 print("w:", w) print("L:", L) print("backward 전 w.grad:", w.grad) L.backward() print("backward 후 w.grad:", w.grad)
w: tensor(3., requires_grad=True) L: tensor(9., grad_fn=<PowBackward0>) backward 전 w.grad: None backward 후 w.grad: tensor(6.)
코드 줄무슨 뜻
w = torch.tensor(3.0, requires_grad=True)값이 3.0인 w를 만들고 기울기를 추적하라고 표시해요.
L = w ** 2L = w² = 9. 이 계산도 기록돼요. 출력의 grad_fn이 "기록 중"이라는 표시예요.
print(w.grad) (첫 번째)아직 backward 전이라 None이에요.
L.backward()L을 w로 미분해요. L = w²이므로 2w = 2×3 = 6을 계산해서 w.grad에 저장해요.
print(w.grad) (두 번째)tensor(6.)이에요.

꼭 알아둘 점이 두 가지 있어요. 첫째, backward()는 w.backward()가 아니라 마지막 값 L에 걸어요. 둘째, backward()는 기울기를 계산해서 저장만 해요. w의 값(3.0)은 그대로이고, 값을 바꾸는 일은 나중에 업데이트(옵티마이저)가 해요.

외우기 팁

미분을 몰라도 시험은 풀 수 있어요. 교수님도 chain rule로 구하든 한 번에 미분하든 값만 맞으면 된다는 취지로 말했어요. 필요한 규칙은 딱 3개예요. ① wⁿ의 기울기는 n × wⁿ⁻¹ (w²는 2w, w³는 3w², w⁴는 4w³) ② 상수 곱하기는 그대로 따라 나와요(3w는 3) ③ 상수만 더한 것은 사라져요(w+1은 1).

이렇게 고르세요 (풀이 요령)

"backward()를 호출하면 무엇이 일어나는가"는 기울기를 계산해 .grad에 저장한다가 정답이에요. "파라미터 값까지 갱신한다"는 보기는 오답이에요. 갱신은 optimizer.step()이 해요.

잠깐 확인 — w=3, loss=(w−1)²에서 backward 후 w.grad는? 그리고 w의 값은 바뀔까요?

w.grad는 2×(3−1) = 4예요. w는 3 그대로예요. backward는 기울기만 계산하고 w 값은 바꾸지 않아요.

6-3. 계산 그래프와 chain rule — 뒤에서 앞으로 곱하기 ★★

모델은 계산이 여러 단계로 이어져 있어요. PyTorch는 계산한 순서를 지도처럼 기록해 두는데 이것이 계산 그래프예요. 그리고 기울기를 구할 때는 이 지도를 뒤에서 앞으로 거슬러 가요.

비유 — 도미노와 톱니바퀴

톱니바퀴가 3개 이어져 있다고 생각해 보세요. 첫 톱니를 1바퀴 돌릴 때 마지막 톱니가 몇 바퀴 도는지는 각 톱니바퀴 사이의 비율을 곱하면 나와요. chain rule(연쇄 법칙)이 바로 "각 단계의 변화 비율을 차례로 곱하기"예요.

교수님 자료의 예제예요. w = 2일 때 a = w², b = 3a, L = b + 1이에요.

w = torch.tensor(2.0, requires_grad=True) a = w ** 2 b = 3 * a L = b + 1 L.backward() print("a =", a.item(), "b =", b.item(), "L =", L.item()) print("dL/dw =", w.grad.item())
a = 4.0 b = 12.0 L = 13.0 dL/dw = 12.0
코드 줄무슨 뜻
a = w ** 2a = 2² = 4
b = 3 * ab = 3 × 4 = 12
L = b + 1L = 12 + 1 = 13
L.backward()뒤에서부터 각 단계의 비율을 곱해요. 1 × 3 × 4 = 12
.item()숫자 하나짜리 Tensor에서 순수한 파이썬 숫자를 꺼내요.

한 번에 미분해도 같은 값이에요. L = 3w² + 1이니까 기울기는 6w이고, w = 2를 넣으면 12예요. 각 단계가 자기 비율만 알면 되기 때문에, 층이 수십 개인 모델도 같은 방식으로 계산할 수 있어요. 이 과정이 신경망의 역전파(backpropagation)예요.

조금 더 모델다운 예제도 볼게요. 예측값 = w × x, 손실 = (예측값 − 정답)²이에요. w = 2, x = 3, 정답 = 10을 넣어요.

w = torch.tensor(2.0, requires_grad=True) x = torch.tensor(3.0) target = torch.tensor(10.0) prediction = w * x loss = (prediction - target) ** 2 loss.backward() print("prediction =", prediction.item()) print("loss =", loss.item()) print("dL/dw =", w.grad.item())
prediction = 6.0 loss = 16.0 dL/dw = -24.0
  • 예측값 = 2 × 3 = 6
  • loss = (6 − 10)² = 16
  • loss를 예측값으로 미분하면 2 × (6 − 10) = −8, 예측값을 w로 미분하면 x = 3이에요. 곱하면 −8 × 3 = −24예요.

기울기가 −24로 음수예요. w를 늘리면 예측값이 10에 가까워지니 loss가 줄어든다는 뜻이에요. 6-1의 표와 맞아요. 또한 기울기는 w의 현재 값을 정한 다음에야 구할 수 있어요. 위치마다 경사가 다르기 때문이에요.

이렇게 고르세요 (풀이 요령)

기울기 값을 묻는 문제는 ① 앞으로 계산해 중간 값(예측값, loss)을 구하고 ② loss를 w로 미분해서 ③ w, x의 숫자를 넣어요. 위 예제에서 w=2, x=3, 정답 10이면 −24예요. 이 숫자들은 교수님 자료에 나온 값이라서 그대로 외워 두면 비슷한 문제에 바로 쓸 수 있어요.

잠깐 확인 — w=2에서 a=w², b=3a, L=b+1일 때 dL/dw를 chain rule로 쓰면?

1 × 3 × 4 = 12예요. dL/db = 1, db/da = 3, da/dw = 2w = 4를 곱해요.

6-4. .grad를 다룰 때 알아야 할 규칙 — leaf, 스칼라

교수님 슬라이드가 정리한 4가지 규칙 중 앞의 두 가지부터 볼게요.

규칙 1. 기울기는 leaf Tensor에만 저장돼요. leaf(잎)는 계산 그래프의 맨 끝에서 만나는 값이에요. 내가 직접 만든 requires_grad=True Tensor와 모델의 weight, bias가 leaf예요. 계산하는 중간에 생긴 값(예 prediction)은 leaf가 아니라서 .grad가 저장되지 않아요.

w = torch.tensor(2.0, requires_grad=True) # leaf x = torch.tensor(3.0) # leaf (추적은 안 함) target = torch.tensor(10.0) prediction = w * x # 중간 값 loss = (prediction - target) ** 2 loss.backward() print("[w.is_leaf]:", w.is_leaf, "[w.grad]:", w.grad) print("[x.is_leaf]:", x.is_leaf, "[x.grad]:", x.grad) print("[prediction.is_leaf]:", prediction.is_leaf, "[prediction.grad]:", prediction.grad)
[w.is_leaf]: True [w.grad]: tensor(-24.) [x.is_leaf]: True [x.grad]: None [prediction.is_leaf]: False [prediction.grad]: None
변수leaf?.grad
wTrue−24 (추적을 켰어요)
xTrueNone (추적을 안 켰어요. 필요 없는 계산을 줄이려고요)
predictionFalseNone (중간 값이에요. 경고 메시지가 같이 나와요)

실제 학습에서는 업데이트할 대상이 weight와 bias이니까 leaf의 .grad만 보면 충분해요.

규칙 2. backward()는 숫자 하나(스칼라)에서 호출해요. loss가 숫자 여러 개짜리 Tensor이면 .sum()이나 .mean()으로 하나로 합친 다음 호출해요. 보통 loss 함수는 원래부터 숫자 하나를 돌려줘요. 반면 기울기를 구하는 대상(파라미터)은 숫자 여러 개짜리여도 괜찮아요.

w = torch.tensor(1.0, requires_grad=True) x = torch.tensor(3.0) L1 = (w * x - 5) ** 2 L2 = (w * x - 7) ** 2 L = torch.stack([L1, L2]) # 숫자 2개짜리 Tensor로 묶음 print("L =", L) L.sum().backward() # 하나로 합쳐서 backward print("w.grad =", w.grad)
L = tensor([ 4., 16.], grad_fn=<StackBackward0>) w.grad = tensor(-36.)
코드 줄무슨 뜻
L1 = (w * x - 5) ** 2(3−5)² = 4
L2 = (w * x - 7) ** 2(3−7)² = 16
torch.stack([L1, L2])두 값을 [4, 16] 한 Tensor로 쌓아요.
L.sum().backward()4 + 16 = 20 하나로 만든 뒤 backward. 기울기는 L1의 −12와 L2의 −24를 더한 −36이에요.
L.backward() (바로)"grad can be implicitly created only for scalar outputs" 오류가 나요.

파라미터가 여러 개짜리일 때는 이렇게 돼요. W = [1, 2, 3], X = [2, 1, 4]이고 b = W @ X(곱해서 더하기), L = b²이면 b = 2+2+12 = 16, L = 256이에요. L.backward() 후 W.grad = [64, 32, 128]이에요. 원소마다 기울기가 따로 계산돼요. 손으로는 2 × b × X의 각 칸 = 32 × [2, 1, 4]로 구해요.

이렇게 고르세요 (풀이 요령)

".grad가 None인 이유"를 묻는 보기는 대개 ① backward를 아직 안 불렀다 ② requires_grad=False이다 ③ leaf가 아닌 중간 값이다 중 하나예요. 그리고 숫자 여러 개짜리 loss에는 .sum() 또는 .mean()을 먼저 쓰고 backward를 불러요.

잠깐 확인 — x = torch.tensor(3.0)처럼 requires_grad를 안 켠 값의 .grad는?

None이에요. 추적을 켜지 않았으니 기울기를 계산하지 않아요.

6-5. 기울기는 쌓여요 — 누적과 zero_grad ★★★

이 장에서 시험에 가장 잘 나올 부분이에요. backward()를 부를 때마다 PyTorch는 기울기를 덮어쓰지 않고 기존 값에 더해요(+=). 이것을 누적이라고 해요.

비유 — 주차 요금 정산기

정산기에 어제 낸 금액이 안 지워진 채로 오늘 금액이 더해지면 총액이 엉망이 돼요. 새 계산을 하기 전에 정산기를 0으로 되돌려야 해요. zero_grad(기울기 0으로 만들기)가 그 "초기화 버튼"이에요.

교수님이 수업에서 든 예예요. 기존에 기울기가 1이었는데 새 기울기 3이 계산되면 덮어써서 3이 되는 게 아니라 더해져서 4가 돼요.

w = torch.tensor(2.0, requires_grad=True) print("초기 grad 값:", w.grad) L1 = w ** 2 L2 = w ** 3 L3 = w ** 4 L1.backward() print("첫 번째 backward 후:", w.grad.item()) L2.backward() print("두 번째 backward 후:", w.grad.item()) w.grad.zero_() # 기울기를 0으로 L3.backward() print("초기화 후 backward:", w.grad.item())
초기 grad 값: None 첫 번째 backward 후: 4.0 두 번째 backward 후: 16.0 초기화 후 backward: 32.0
단계그 단계의 기울기저장된 .grad
L1 = w² backward2w = 2×2 = 44
L2 = w³ backward3w² = 3×4 = 124 + 12 = 16
zero_()—0으로 지워요
L3 = w⁴ backward4w³ = 4×8 = 320 + 32 = 32

왜 누적이 기본일까요? 같은 파라미터가 여러 경로로 loss에 영향을 주면, 각 경로의 기울기를 모두 더해야 전체 기울기가 되기 때문이에요. 하지만 보통 학습에서는 loss가 하나뿐이라서 매번 직접 지워 줘야 해요.

또 하나의 규칙이 규칙 4. 같은 계산 그래프는 한 번만 backward할 수 있다는 거예요. backward를 하면 메모리를 아끼려고 기록(그래프)을 풀어 버려요. 같은 L에서 또 부르면 오류가 나요. 다시 하려면 forward(계산)를 새로 해서 그래프를 다시 만들어야 해요.

w = torch.tensor(2.0, requires_grad=True) L1 = w ** 2 L1.backward() print("첫 번째 backward 후:", w.grad.item()) # L1.backward() ← 다시 부르면 RuntimeError w.grad.zero_() # 기울기 초기화 L1 = w ** 2 # forward를 다시 해서 새 그래프를 만든다 L1.backward() print("새 그래프의 backward:", w.grad.item())
첫 번째 backward 후: 4.0 새 그래프의 backward: 4.0

교수님 자료의 기본 실습 2는 두 가지가 별개라는 점을 보여 줘요. 새 forward는 그래프를 새로 만들 뿐 .grad를 지우지 않아요. w = 2에서 loss = w²를 backward → 4, loss를 새로 계산해 다시 backward(초기화 없이) → 8, zero_() 후 → 0, 새 loss로 backward → 4예요.

하고 싶은 일해야 하는 것왜
이전 기울기 지우기grad.zero_() / optimizer.zero_grad()기울기가 쌓이기 때문이에요.
backward를 또 하기forward부터 다시그래프가 한 번 쓰면 풀려요.

실제 학습 루프에서는 매번 pred = model(x), loss = criterion(pred, y)를 새로 계산하니까 그래프 재사용 문제는 없어요. 대신 매 반복마다 기울기는 꼭 지워야 해요. 이것이 학습 5단계의 맨 앞 zero_grad예요(9장).

외우기 팁

"새 forward ≠ 기울기 초기화". 그래프를 새로 만드는 것과 기울기를 지우는 것은 서로 상관없는 두 가지 일이에요. 4 → 8 → 0 → 4 순서를 기억하세요.

이렇게 고르세요 (풀이 요령)

backward를 여러 번 호출하는 코드의 출력은 "앞 기울기 + 이번 기울기"를 손으로 더해 가면 나와요. 중간에 zero_()나 zero_grad()가 있으면 그 줄부터 0에서 다시 시작해요. 예를 들어 w=2에서 w² → w³ → (zero) → w⁴이면 4 → 16 → 32예요.

잠깐 확인 — w=2에서 L=w²를 backward하고, zero 없이 loss를 새로 계산해 또 backward하면 w.grad는?

8이에요. 첫 번째 4에 두 번째 4가 더해져요. 새로 forward를 했어도 .grad는 지워지지 않아요.

6-6. torch.no_grad() — 기록을 잠깐 끄기 ★★

Autograd는 계산을 계속 기록하느라 메모리와 시간을 써요. 기록이 필요 없는 순간에는 with torch.no_grad():로 감싸서 꺼요. 이 블록 안의 계산만 기록에서 빠지고, 블록 밖으로 나오면 다시 기록해요.

꺼야 하는 대표적인 경우가 두 가지예요.

  1. 파라미터를 직접 업데이트할 때 — requires_grad=True인 leaf를 -=처럼 제자리(in-place)에서 고치면 오류가 나요. 그래서 no_grad 안에서 해요.
  2. 평가나 예측을 할 때 — 값을 안 고칠 거라서 기울기가 필요 없어요. 끄면 계산이 빨라지고 메모리가 줄어요(9장).
w = torch.tensor(2.0, requires_grad=True) x = torch.tensor(3.0) target = torch.tensor(10.0) loss = (w * x - target) ** 2 loss.backward() # 기울기 계산 print("grad:", w.grad.item()) learning_rate = 0.01 with torch.no_grad(): # 추적을 끄고 w -= learning_rate * w.grad # 제자리에서 업데이트 print("업데이트 후 w:", round(w.item(), 2)) print("requires_grad:", w.requires_grad)
grad: -24.0 업데이트 후 w: 2.24 requires_grad: True
코드 줄무슨 뜻
loss.backward()w의 기울기 −24를 계산해 w.grad에 저장해요.
with torch.no_grad():이 아래 들여쓴 줄에서는 기록을 꺼요.
w -= learning_rate * w.gradw = 2 − 0.01 × (−24) = 2.24. -=는 제자리 수정이라 실제 w 값이 바뀌어요.
w.requires_grad그대로 True예요. 블록 안만 잠깐 끈 것이라서 다음 학습에서 다시 기록해요.

모델이 크면 파라미터마다 이 줄을 쓰기 번거로워서 model.parameters()로 한꺼번에 돌아요. 과제 1의 5번 빈칸이 바로 이 구조예요.

with torch.no_grad(): for parameter in model.parameters(): parameter -= learning_rate * parameter.grad

조심할 점이 있어요. parameter = parameter - ...처럼 쓰면 새 Tensor가 만들어질 뿐 모델 안의 값은 안 바뀌어요. 꼭 -=로 써야 해요. 그리고 나중에 배울 옵티마이저를 쓰면 step()이 이 일을 알아서 처리해서 no_grad로 따로 감쌀 필요가 없어요.

이렇게 고르세요 (풀이 요령)

"torch.no_grad()의 효과"는 블록 안의 연산만 기울기 추적에서 제외한다예요. requires_grad=True 설정 자체가 바뀌는 것은 아니에요. 블록 안에서 만든 결과는 requires_grad=False이고, 기존 w는 True 그대로예요.

잠깐 확인 — no_grad 블록 안에서 w -= lr * w.grad를 하면 w.requires_grad가 False가 될까요?

아니에요. 그대로 True예요. no_grad는 블록 안의 연산 기록만 끄고 설정은 바꾸지 않아요.

6-7. 손으로 기울기 값 구하기와 자주 나는 문제 ★★

교수님이 시험을 "코드를 주고 결과를 쓰는" 객관식으로 낸다고 했어요. 이 장에서 나올 수 있는 유형은 기울기 값 계산과 누적 결과예요. 순서만 익히면 쉬워요.

  1. 앞으로 계산해서 예측값과 loss의 숫자를 구해요.
  2. loss를 w로 미분하는 식을 세워요. (예측값 − 정답)²이면 2 × (예측값 − 정답) × x예요.
  3. 숫자를 넣어요.
  4. backward()가 여러 번이면 더하고, 중간에 zero가 있으면 0부터 다시 시작해요.

연습 문제 두 개를 풀어 볼게요. 직접 실행해서 확인한 값이에요.

w = torch.tensor(1.0, requires_grad=True) loss = (w * 2 - 7) ** 2 loss.backward() print(loss.item(), w.grad.item())
  • 예측값 = 1 × 2 = 2, 정답 7이니 loss = (2 − 7)² = 25
  • 기울기 = 2 × (2 − 7) × 2 = −20
  • 출력은 25.0 -20.0이에요.
w = torch.tensor(2.0, requires_grad=True) for i in range(3): L = w ** 2 L.backward() print(w.grad.item())
  • 매번 기울기 2w = 4가 새로 계산되지만 지우지 않아서 계속 더해져요.
  • 출력은 4.0, 8.0, 12.0이에요.

마지막으로 교수님 자료의 오류 점검표를 요약해요. 증상이 나오면 원인을 고르는 문제가 가능해요.

증상원인
.grad가 Nonebackward 전이에요 / requires_grad=False예요 / leaf가 아닌 중간 값이에요
기울기가 예상보다 커요이전 기울기가 누적됐어요 (zero_grad 위치 확인)
두 번째 backward에서 오류같은 계산 그래프를 다시 썼어요 (forward를 다시 해요)
backward에서 "does not require grad" 오류detach(), no_grad(), .item() 등으로 계산 그래프가 끊겼어요
숫자 여러 개짜리 loss에서 오류스칼라가 아니에요 (.sum(), .mean()으로 합쳐요)
이렇게 고르세요 (풀이 요령)

Autograd 설명 보기에서 맞는 문장은 이 두 개예요. "requires_grad=True인 Tensor의 연산을 계산 그래프로 기록하고, backward()가 chain rule로 leaf Tensor의 기울기를 계산해 .grad에 저장한다." "기울기는 덮어쓰이지 않고 누적되므로 매 학습 단계마다 zero_grad()로 초기화해야 한다." 반대로 "backward()가 파라미터 값까지 바꾼다"거나 "기울기는 매번 자동으로 새로 시작한다"는 보기는 오답이에요.

잠깐 확인 — 학습할 때 기울기를 매번 0으로 만들지 않으면 어떤 일이 생기나요?

이전 단계의 기울기가 계속 더해져서 기울기가 실제보다 커져요. 그러면 파라미터를 엉뚱한 방향과 크기로 업데이트하게 돼요.

이 장 3줄 요약
  • 기울기는 loss를 줄일 방향(부호)과 민감도(크기)를 알려 줘요. requires_grad=True로 추적을 켜고 loss에서 backward()를 호출하면 leaf Tensor의 .grad에 chain rule로 계산한 값이 저장돼요(w=3, L=w²이면 6 / w=2, x=3, 정답 10이면 −24).
  • backward()는 스칼라 loss에서 한 번만 호출할 수 있고(그래프는 한 번 쓰면 풀려요), 기울기는 누적되기 때문에 zero_grad가 필요해요. 새 forward와 기울기 초기화는 별개예요(4 → 8 → 0 → 4).
  • 파라미터를 직접 업데이트하거나 평가할 때는 with torch.no_grad():로 추적을 꺼요. 블록 안의 연산만 제외되고 requires_grad=True는 유지돼요. 옵티마이저의 step()은 이것을 알아서 처리해요.
