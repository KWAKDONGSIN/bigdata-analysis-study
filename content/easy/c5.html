nn.Module로 모델 만들기 — 숫자를 넣으면 예측이 나오는 계산기 상자

딥러닝 모델은 파이썬 클래스 하나로 만들어요. 이 장에서는 그 뼈대(__init__과 forward), 한 층을 만드는 nn.Linear(입력, 출력), 그리고 model(x)가 forward를 실행하는 과정을 배워요. 샘플 시험 3번이 바로 이 장이에요.

5-1. 모델은 클래스예요 — nn.Module 뼈대 ★★★

앞 장에서 클래스(설계도)와 상속(부모의 기능을 물려받기)을 배웠죠. PyTorch에서 모델을 만들 때는 부모 클래스 nn.Module을 물려받아서 나만의 모델 클래스를 만들어요. nn.Module에는 모델이 일하는 데 필요한 기본 기능이 이미 들어 있어요.

비유

모델은 계산기 상자예요. 상자를 만들 때(__init__) 안에 쓸 부품(층)을 넣어 두고, 숫자가 들어오면(forward) 어떤 순서로 계산해서 결과를 내보낼지 적어 둬요. 교수님 자료도 __init__은 층과 구성 요소를 정의하고 등록하는 곳, forward는 입력에서 출력까지의 계산 흐름을 정의하는 곳이라고 정리했어요.

import torch from torch import nn class MyModel(nn.Module): # nn.Module을 물려받는다 def __init__(self): super().__init__() # 부모 준비를 가장 먼저 # 여기서 층(layer)을 만들어 self에 붙인다 def forward(self, x): # 입력 x가 들어오면 어떻게 계산할지 쓴다 return x # 계산 결과를 돌려준다
코드 줄무슨 뜻
class MyModel(nn.Module):"MyModel은 nn.Module의 자식이다."
def __init__(self):모델을 처음 만들 때 한 번 실행되는 곳. 층을 만들어 두는 자리예요.
super().__init__()부모(nn.Module)의 준비 작업을 실행해요. 층과 파라미터를 관리할 준비를 하는 거예요.
def forward(self, x):입력 x에서 출력까지의 계산 흐름을 쓰는 곳. 이름은 꼭 forward여야 해요.
return x계산 결과를 내보내요.

왜 super().__init__()을 맨 앞에 쓸까요? 자식 클래스가 __init__을 직접 만들면 부모의 __init__은 자동으로 실행되지 않아요. 그래서 "부모 것도 실행해 줘"라고 직접 불러야 해요. 안 부르면 층을 붙이는 순간 오류가 나요.

외우기 팁

모델 뼈대 3줄은 클래스 이름 뒤에 (nn.Module) / 첫 줄에 super().__init__() / 계산은 forward예요.

이렇게 고르세요 (풀이 요령)

모델 코드가 나오면 먼저 세 가지를 확인하세요. ① (nn.Module)을 물려받았는지 ② __init__ 맨 앞에 super().__init__()이 있는지 ③ 계산이 forward 안에 있는지. 보기에서 "층은 __init__에서 만들고 계산 흐름은 forward에서 정의한다"는 문장이 맞는 설명이에요.

잠깐 확인 — __init__ 안에서 super().__init__()을 빼먹고 self.fc = nn.Linear(3, 2)를 쓰면 어떻게 될까요?

오류가 나요. 직접 실행해 보면 "cannot assign module before Module.__init__() call"이라는 메시지가 나와요. 부모의 준비 작업이 끝나기 전에는 층을 붙일 수 없다는 뜻이에요.

5-2. 가장 쉬운 한 층 모델 — x @ W.T + B ★★★

딥러닝에서 한 층(layer)은 "입력 숫자 여러 개를 섞어서 출력 숫자 여러 개로 바꾸는 계산"이에요. 용어부터 풀어 볼게요.

  • 특성(feature) : 입력 숫자 하나하나예요. 학생 정보라면 중간고사 점수, 공부 시간 같은 것이에요.
  • 배치(batch) : 한 번에 넣는 데이터 묶음이에요. 학생 4명을 한꺼번에 넣으면 배치 크기는 4예요.
  • 가중치(weight, W) : 각 입력에 곱하는 "중요도 점수"예요.
  • 편향(bias, B) : 마지막에 더하는 "기본 점수"예요.
비유

성적 환산과 같아요. "국어 × 0.3 + 영어 × 0.3 + 수학 × 0.4 + 가산점 5점"처럼, 각 점수에 반영 비율(W)을 곱해서 더하고 마지막에 가산점(B)을 더해요. 딥러닝은 이 비율과 가산점을 학습으로 찾아내요.

3주차 업데이트본에서 교수님은 이 계산을 nn.Linear 없이 직접 써서 보여 줬어요. "nn.Linear가 바로 나오면 점프가 크다"는 질문이 많았기 때문이에요. 먼저 숫자를 직접 정한 모델을 볼게요.

import torch from torch import nn class MyModel(nn.Module): def __init__(self): super().__init__() # 입력 특성 3개 → 출력 특성 2개 self.W = torch.tensor([[1., 0., 2.], [0., 1., 1.]]) # 크기 (2, 3) self.B = torch.tensor([0.5, -1.0]) # 크기 (2,) def forward(self, x): return x @ self.W.T + self.B model = MyModel() x = torch.tensor([[1., 2., 3.], [0., 0., 1.], [1., 1., 1.], [2., 0., 0.]]) # 크기 (4, 3) y = model(x) print(y) print(y.shape)

실행 결과는 아래와 같아요.

tensor([[ 7.5000, 4.0000], [ 2.5000, 0.0000], [ 3.5000, 1.0000], [ 2.5000, -1.0000]]) torch.Size([4, 2])
코드 줄무슨 뜻
self.W = torch.tensor([[1,0,2],[0,1,1]])가중치 W. 2줄 × 3칸이라 크기가 (2, 3)이에요. 한 줄이 출력 하나를 만드는 비율표예요.
self.B = torch.tensor([0.5, -1.0])편향 B. 출력이 2개라서 숫자 2개예요.
x @ self.W.T@는 행렬 곱셈이에요. .T는 W의 가로세로를 뒤집은 것(전치)이라서 (3, 2)가 돼요.
+ self.B결과의 모든 줄에 B를 똑같이 더해요. 작은 것을 알아서 늘려 맞추는 것을 브로드캐스팅(broadcasting)이라고 해요.
y = model(x)x를 모델에 넣어 예측 y를 얻어요. 크기는 (4, 2)예요.

첫 번째 학생 [1, 2, 3]을 손으로 계산해 볼게요.

  • 첫 번째 출력 = 1×1 + 0×2 + 2×3 + 0.5 = 7.5
  • 두 번째 출력 = 0×1 + 1×2 + 1×3 − 1 = 4.0

W의 첫 줄 [1, 0, 2]가 첫 번째 출력을 만드는 비율표이고, 둘째 줄 [0, 1, 1]이 두 번째 출력의 비율표예요. 나머지 3명도 같은 방식이에요.

이름크기설명
입력 x(4, 3)데이터 4개, 각각 특성 3개
가중치 W(2, 3)(출력 개수, 입력 개수)
뒤집은 W.T(3, 2)곱셈을 맞추려고 뒤집어요
편향 B(2,)출력 개수만큼
출력 y(4, 2)데이터 4개, 각각 출력 2개
크기 계산 규칙

(m, k) @ (k, n) = (m, n). 안쪽 숫자(k)가 같아야 곱할 수 있고, 바깥 숫자 둘이 결과의 크기가 돼요. W를 (출력, 입력)으로 만들고 .T로 뒤집는 이유가 바로 이 규칙 때문이에요.

이렇게 고르세요 (풀이 요령)

"입력 특성 3개를 출력 특성 2개로 바꾼다"는 문장이 있으면 W는 (2, 3), B는 (2,), 출력은 (배치 크기, 2)예요. 숫자를 외우지 말고 "W는 (출력, 입력)"만 기억하세요. 입력의 마지막 숫자(특성 개수)가 W의 두 번째 숫자와 같지 않으면 곱셈이 안 돼서 오류가 나요.

잠깐 확인 — 입력 x가 (5, 4)이고 입력 특성 4개를 출력 3개로 바꾸는 모델이면 W와 y의 크기는?

W는 (3, 4), B는 (3,), 출력 y는 (5, 3)이에요. (5, 4) @ (4, 3) = (5, 3)이 되고 B가 5줄에 똑같이 더해져요.

5-3. nn.Linear(입력, 출력) — 같은 계산을 한 줄로 ★★★

W와 B를 매번 직접 만들고 x @ W.T + B를 쓰는 건 번거로워요. 그래서 PyTorch가 이 일을 해 주는 부품을 미리 만들어 뒀어요. 그게 nn.Linear예요. Linear는 "선형(일차식) 계산"이라는 뜻이에요.

한 줄 정의

nn.Linear(in_features, out_features) = 입력 특성 개수, 출력 특성 개수를 넣으면 W와 B를 자동으로 만들고, 호출하면 x @ W.T + B를 계산해 주는 층이에요.

fc = nn.Linear(3, 2) # 입력 특성 3개 → 출력 특성 2개 print(fc.weight.shape) print(fc.bias.shape) x = torch.ones(4, 3) # 데이터 4개, 특성 3개 print(fc(x).shape)
torch.Size([2, 3]) torch.Size([2]) torch.Size([4, 2])
코드 줄무슨 뜻
nn.Linear(3, 2)앞 숫자가 입력, 뒤 숫자가 출력이에요. 입력 3개를 출력 2개로 바꿔요.
fc.weight.shape자동으로 만들어진 가중치. 크기는 (출력, 입력) = (2, 3)이에요. 괄호 안 순서와 반대라서 헷갈리기 쉬워요.
fc.bias.shape편향. 크기는 (출력,) = (2,)예요.
fc(x)층도 함수처럼 부를 수 있어요. 결과 크기는 (4, 2)예요.

입력 3개가 출력 2개와 모두 선으로 이어져요. 이 선 하나하나가 가중치이고, 출력 칸마다 편향이 하나씩 붙어요. 그래서 학습할 숫자(파라미터) 개수 = 입력 × 출력 + 출력이에요.

class MyModel(nn.Module): def __init__(self): super().__init__() self.fc = nn.Linear(in_features=3, out_features=2) def forward(self, x): return self.fc(x) model = MyModel() x = torch.ones(4, 3) y = model(x) print(tuple(y.shape)) for name, p in model.named_parameters(): print(name, tuple(p.shape))

return self.fc(x)x를 층에 넣은 결과를 돌려줘요. 괄호와 x를 꼭 써야 계산이 실행돼요.

외우기 팁

nn.Linear(입력, 출력)은 말하는 순서 그대로 써요("3개를 2개로"). 하지만 안에 든 weight는 (출력, 입력)이라 반대로 저장돼요. 문제에서 nn.Linear(2, 3)처럼 순서가 뒤집힌 보기는 오답이에요.

이렇게 고르세요 (풀이 요령)

① 문제 설명에서 "입력 특성 몇 개 → 출력 특성 몇 개"를 찾아요. ② 그 순서대로 nn.Linear(입력, 출력)을 골라요. ③ 입력의 첫 숫자(torch.ones(4, 3)의 4)는 배치 크기라서 Linear 숫자와 상관없어요. 4와 3을 헷갈려 nn.Linear(4, 2)를 고르면 틀려요.

잠깐 확인 — nn.Linear(10, 5)의 weight 크기와 파라미터 개수는?

weight는 (5, 10)이고 bias는 (5,)예요. 파라미터는 10×5 + 5 = 55개예요.

5-4. model(x)는 어떻게 forward를 실행할까 — __call__ ★★★

코드를 보면 forward를 만들었는데 실제로는 model.forward(x)가 아니라 model(x)라고 불러요. 이상하죠. 교수님이 여러 번 강조한 부분이라서 순서대로 따라가 볼게요.

비유 — 식당 접수대

손님(x)이 바로 주방(forward)으로 들어가지 않고 접수대(__call__)를 먼저 거쳐요. 접수대는 번호표를 주고 기록을 남기는 등 부가 업무를 한 다음 주방에 주문을 넘겨요. 접수대는 식당 본사(부모 nn.Module)가 이미 만들어 뒀고, 주방(forward)만 우리 가게(자식 클래스)가 직접 꾸려요.

먼저 앞 장에서 배운 __call__을 복습할게요. 클래스에 __call__을 만들어 두면 그 인스턴스를 함수처럼 f(3)로 부를 수 있어요. 교수님은 __call__ 안에서 forward를 부르는 예를 보여 줬어요.

class AffineFunction: def __init__(self, a, b): self.a = a self.b = b def __call__(self, x): return self.forward(x) def forward(self, x): print("forward() 호출됨") return self.a * x + self.b m1 = AffineFunction(a=2, b=1) print("f(3):", m1(3)) print("f(10):", m1(10))
forward() 호출됨 f(3): 7 forward() 호출됨 f(10): 21
코드 줄무슨 뜻
m1 = AffineFunction(a=2, b=1)a=2, b=1인 객체를 만들어요. 이때 __init__이 한 번 실행돼요.
m1(3)괄호로 부르면 파이썬이 m1.__call__(3)을 실행해요.
return self.forward(x)__call__이 다시 forward를 불러요. 그래서 "forward() 호출됨"이 찍혀요.
2 * 3 + 1forward의 계산이에요. 결과 7. m1(10)은 2×10+1 = 21이에요.

nn.Module이 하는 일이 바로 이거예요. 우리가 만든 MyModel에는 __call__이 없어요. 그래서 파이썬은 부모 nn.Module에서 물려받은 __call__을 찾아 실행하고, 그 안에서 우리가 만든 forward가 실행돼요.

  1. y = model(x)를 써요.
  2. 부모 nn.Module의 __call__(x)가 실행돼요.
  3. 그 안에서 ① hook(따로 만든 경우에만) ② 그밖의 상태 관리 처리 ③ forward(x) 실행이 차례로 일어나요.
  4. 결과 y(출력 Tensor)가 나와요.
방법판정이유
y = model(x)정답__call__의 부가 처리를 모두 거쳐요.
y = model.forward(x)하지 말 것계산은 되지만 hook 같은 부가 처리를 건너뛰어요.
__call__을 내가 다시 정의하지 말 것부모가 하던 중요한 처리를 못 해서 호출 기능이 제대로 안 될 수 있어요.

한 가지 더. 모델을 만들 때(model = MyModel()) __init__이 한 번 실행되고, model(x)를 부를 때마다 forward가 실행돼요. model(x)가 __init__을 다시 실행하는 일은 없어요.

이렇게 고르세요 (풀이 요령)

"model(x)의 호출 과정" 보기에서 "상속받은 __call__()의 호출 처리를 거쳐 forward() 실행"이 맞아요. "__init__()을 다시 실행하여 출력 계산"이 들어 있으면 바로 오답이에요. __init__은 모델을 만들 때 한 번뿐이에요.

잠깐 확인 — forward 함수를 만들지 않고 model(x)를 부르면 어떻게 될까요?

NotImplementedError가 나요. __call__이 실행할 forward가 없기 때문이에요.

5-5. nn.Parameter — 학습할 값은 "등록"해야 해요

모델이 학습한다는 것은 W와 B 같은 숫자를 조금씩 고친다는 뜻이에요. 그러려면 모델이 "내가 고쳐야 할 숫자는 이것들이야"라고 알고 있어야 해요. 이 목록에 올리는 일을 등록이라고 해요.

한 줄 정의

nn.Parameter로 감싼 Tensor를 모델의 속성(self.이름)에 붙이면 학습할 파라미터로 자동 등록돼요. 등록된 것은 requires_grad=True가 기본이고 model.parameters()에 나와요.

비유

출석부와 같아요. 출석부(parameters())에 이름이 올라야 선생님(옵티마이저)이 불러 주고 점검해요. 일반 Tensor는 출석부에 이름이 없어서, 아무리 열심히 계산에 참여해도 업데이트 명단에서 빠져요.

class RegistrationModel(nn.Module): def __init__(self): super().__init__() self.tensor_w = torch.tensor(2.0, requires_grad=True) self.parameter_w = nn.Parameter(torch.tensor(2.0)) def forward(self, x): return self.tensor_w * x + self.parameter_w * x model = RegistrationModel() print("등록된 이름:", [name for name, _ in model.named_parameters()])
등록된 이름: ['parameter_w']
코드 줄무슨 뜻
torch.tensor(2.0, requires_grad=True)일반 Tensor예요. 기울기는 계산되지만 모델 파라미터로는 등록되지 않아요.
nn.Parameter(torch.tensor(2.0))"학습할 값"이라고 표시한 Tensor예요. self에 붙이면 자동 등록돼요.
model.named_parameters()(이름, 값) 쌍을 차례로 보여줘요. parameters()는 값만 보여줘요.

결과에 parameter_w만 나와요. 교수님은 "사람들이 흔히 빠지는 함정"이라고 했어요. 나중에 model.parameters()로 한꺼번에 업데이트할 때 tensor_w는 빠져서 학습이 안 되기 때문이에요.

nn.Linear 안에 있는 weight와 bias는 이미 nn.Parameter로 되어 있어요. 그래서 nn.Linear를 쓰면 등록 걱정을 안 해도 돼요. 층이 많아지면 어느 층의 어떤 값인지 이름과 함께 봐야 하니까 named_parameters()를 더 많이 써요. 보통은 값보다 크기(shape)를 찍어서 확인해요.

이렇게 고르세요 (풀이 요령)

"기울기(grad)가 계산되는 것"과 "model.parameters()에 포함되는 것"은 다른 이야기예요. requires_grad=True인 일반 Tensor는 기울기는 계산되지만 파라미터에 포함되지 않아요. nn.Parameter를 모델 속성에 할당해야 등록돼요.

잠깐 확인 — self.fc = nn.Linear(3, 2)를 쓴 모델에서 named_parameters()에 나오는 이름 2개는?

fc.weight와 fc.bias예요. 속성 이름(fc) 뒤에 층 안의 이름이 점으로 이어져요.

5-6. 층 쌓기 — ReLU, nn.Sequential, 다층 모델

실제 모델은 층을 여러 개 이어 붙여요. 첫 층의 출력이 다음 층의 입력이 되는 구조예요. 층 사이에는 보통 ReLU를 끼워 넣어요.

ReLU

숫자별로 0보다 작으면 0으로, 0 이상이면 그대로 바꾸는 계산이에요. 크기(shape)는 변하지 않아요. 예를 들어 [-2, 0, 3]은 [0, 0, 3]이 돼요. 학습할 숫자가 없어서 파라미터도 없어요.

참고로, 층 사이에 ReLU 같은 계산이 없으면 선형 계산을 여러 번 해도 결국 선형 계산 한 번과 같아져요. 그래서 층을 쌓을 때 ReLU를 끼워 넣어요.

층을 순서대로 이어 붙이기만 하면 되는 모델은 nn.Sequential(차례대로 쌓기)로 간단히 만들 수 있어요. 클래스를 따로 만들 필요가 없어요.

seq = nn.Sequential( nn.Linear(4, 5), nn.ReLU(), nn.Linear(5, 2), ) x = torch.randn(4, 4) y = seq(x) print(tuple(y.shape)) for name, p in seq.named_parameters(): print(name, tuple(p.shape))
(4, 2) 0.weight (5, 4) 0.bias (5,) 2.weight (2, 5) 2.bias (2,)
코드 줄무슨 뜻
nn.Linear(4, 5)첫 번째 층. 특성 4개를 5개로 바꿔요. (4, 4) → (4, 5)
nn.ReLU()음수를 0으로. 크기는 그대로 (4, 5)
nn.Linear(5, 2)두 번째 층. 앞 층 출력 5개를 받아 2개로 바꿔요. (4, 5) → (4, 2)
0.weight, 2.weight이름은 층 번호예요. 1번인 ReLU는 파라미터가 없어서 이름에 안 나와요.

파라미터 개수는 (4×5+5) + (5×2+2) = 25 + 12 = 37개예요. 층을 이을 때는 앞 층의 출력 개수 = 다음 층의 입력 개수여야 해요. 5와 5가 맞았죠.

그렇다면 직접 클래스를 만드는 모델은 언제 필요할까요? 교수님 자료에 정리돼 있어요. 계산 흐름이 갈라지거나 합쳐질 때예요.

상황예시
여러 경로 결과를 합칠 때fc1(x) + fc2(x)
입력을 중간 결과에 더할 때(잔차 연결)x + layer(x)
입력이 여러 개일 때이미지와 숫자 데이터를 함께 입력
결과를 여러 개 돌려줄 때예측값과 중간 특징을 함께 반환
조건문이나 반복문이 필요할 때조건에 따라 다른 층 실행
class MyModel(nn.Module): def __init__(self): super().__init__() self.fc2 = nn.Linear(3, 2) self.fc1 = nn.Linear(3, 2) def forward(self, x): y1 = self.fc1(x) y2 = self.fc2(x) return y1 + y2 # Sequential로는 만들 수 없다

같은 입력 x가 두 길로 갈라져 갔다가 결과를 더해요. 한 줄로만 이어지는 Sequential로는 표현할 수 없어요. 파라미터는 층 2개라서 (3×2+2) × 2 = 16개예요.

교수님이 낸 과제 1은 이 생각을 늘린 것이에요. 입력 (10, 8)이 8 → 4 → 6 → 2 순서로 지나가요. 각 층 사이에 ReLU를 쓰되 마지막 출력에는 ReLU를 쓰지 않아요. 파라미터는 36 + 30 + 14 = 80개예요. forward에서는 x = ...처럼 같은 변수 x를 계속 덮어쓰는 것이 관례예요.

이렇게 고르세요 (풀이 요령)

다층 모델 문제는 출력 크기를 층마다 손으로 따라가면 풀려요. 예를 들어 입력 (4, 3)에 nn.Linear(3, 5) → ReLU → nn.Linear(5, 2)이면 (4, 3) → (4, 5) → (4, 5) → (4, 2)예요. 앞 층 출력 개수와 다음 층 입력 개수가 다르면 오류예요.

잠깐 확인 — nn.Sequential(nn.Linear(4, 5), nn.ReLU(), nn.Linear(5, 2))에서 ReLU의 이름 번호가 왜 안 나올까요?

ReLU에는 학습할 파라미터가 없기 때문이에요. 0.weight, 0.bias, 2.weight, 2.bias만 나오고 번호 1은 건너뛰어요.

5-7. 샘플 시험 3번 손으로 풀기와 자주 나오는 오류 ★★★

이제 시험 문제를 풀 준비가 됐어요. 문제 내용은 이래요. 모델이 입력 특성 3개를 출력 특성 2개로 바꾸고, 빈칸 (A)에는 층을 만드는 코드, (B)에는 forward가 돌려줄 값을 써야 해요. 입력은 torch.ones(4, 3)이고 출력 크기가 (4, 2)가 되어야 해요.

class MyModel(nn.Module): def __init__(self): super().__init__() self.fc = __________ # (A) def forward(self, x): return __________ # (B)
  1. (A) 찾기 — 입력 3개, 출력 2개이니 nn.Linear(3, 2)예요. 보기 ①의 (2, 3)은 순서가 뒤집혔어요. 보기 ④의 (4, 2)는 배치 크기 4를 입력 특성으로 착각한 거예요.
  2. (B) 찾기 — 층에 x를 넣어야 계산돼요. self.fc(x)가 맞아요. self.fc만 쓰면 층 상자 자체를 돌려줄 뿐 계산하지 않아서 보기 ③은 오답이에요.
  3. model(x)의 호출 과정 — "상속받은 __call__()의 호출 처리를 거쳐 forward() 실행"이 맞아요. "__init__()을 다시 실행"은 보기 ②, ④에 있는데 둘 다 틀려요.

세 조건을 모두 만족하는 것은 (A) nn.Linear(3, 2), (B) self.fc(x), 호출 과정은 __call__ 경유인 ⑤번이에요.

이렇게 고르세요 (풀이 요령)

표로 된 보기는 열마다 지우는 방식으로 풀어요. (A) 열에서 입력→출력 순서가 틀린 보기를 지우고, (B) 열에서 괄호나 x가 빠진 보기를 지우고, 마지막 열에서 "__init__ 다시 실행"을 지우면 하나만 남아요.

마지막으로 교수님 자료에 나온 자주 발생하는 오류 3가지를 정리해요. 실제로 실행해서 나온 메시지예요.

실수나오는 오류이유
super().__init__()을 빼먹음AttributeError ("cannot assign module before Module.__init__() call")부모의 준비가 안 돼서 층을 등록할 수 없어요.
forward를 정의하지 않음NotImplementedError ("missing the required forward function")model(x)가 실행할 계산 흐름이 없어요.
Linear 입력 크기와 데이터가 안 맞음RuntimeError ("mat1 and mat2 shapes cannot be multiplied")nn.Linear(4, 3)에는 마지막 차원이 4인 데이터를 넣어야 해요.
잠깐 확인 — nn.Linear(4, 3)에 (2, 5) 크기의 데이터를 넣으면?

오류가 나요. 마지막 차원이 5인데 Linear는 4를 기대해서 곱셈이 안 되기 때문이에요. 이때 오류 메시지에 "2x5 and 4x3"처럼 두 크기가 찍혀요.

이 장 3줄 요약
  • 모델은 nn.Module을 물려받은 클래스예요. __init__에서 super().__init__()을 맨 먼저 쓰고 층을 만들며, forward에서 계산 흐름을 써요.
  • nn.Linear(입력, 출력)은 x @ W.T + B를 해 주는 층이에요. weight는 (출력, 입력), bias는 (출력,), 파라미터 개수는 입력×출력+출력이고, 출력은 (배치, 출력)이에요.
  • model(x)를 쓰면 부모의 __call__을 거쳐 forward가 실행돼요. __init__은 모델을 만들 때 한 번뿐이고, 일반 Tensor가 아니라 nn.Parameter(또는 nn.Linear)여야 파라미터로 등록돼요.
