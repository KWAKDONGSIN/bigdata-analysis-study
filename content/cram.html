새벽 압축 암기장

코드는 짜는 게 아니라 읽기만 해요. 이 페이지를 2번 훑고, 그다음 핵심 문제를 푸세요.

통째로 외울 2줄

학습 5줄 — zero_grad → forward(예측) → loss → backward → step

모델 클래스 틀 — nn.Module 상속 → super().__init__() → self에 층 등록 → forward → model(x)는 __call__을 거쳐 forward 실행

코드 읽기 규칙 10개

  1. 인덱스는 0부터 센다. a[1:3]은 1번, 2번만 (끝 번호 미포함).
  2. 숫자로 뽑으면 차원이 사라지고(x[:,1] → (3,)), 범위로 뽑으면 남는다(x[:,1:2] → (3,1)).
  3. reshape는 원소 수의 곱이 같아야 한다. 12개는 (3,4), (4,3), (2,6)이 되고 (5,3)은 안 된다.
  4. shape 계산은 오른쪽 끝부터. 같거나, 하나가 1이거나, 한쪽에 없으면 브로드캐스팅 가능하다. sum(dim=k)는 k번 차원이 사라진다.
  5. nn.Linear(in, out)은 마지막 차원 in을 out으로 바꾸고 맨 앞 batch는 유지한다. 파라미터 수 = in×out + out.
  6. backward는 grad를 계산해 저장만 하고, 값을 바꾸는 건 step이다.
  7. grad는 덮어쓰기가 아니라 더하기로 쌓인다. 그래서 매번 zero_grad.
  8. DataLoader 배치 수 = 올림(샘플 수 ÷ batch). 마지막 batch 크기 = 나머지. 10개, batch 4면 [4,4,2].
  9. 자식이 __init__을 다시 쓰면 부모 __init__은 자동 실행이 안 되니 super().__init__()이 필요하다.
  10. 자식이 부모와 같은 이름의 메서드를 쓰면(오버라이딩) 자식 것만 실행된다. 보기에 "항상 · 자동으로"가 있으면 의심하라.

시험 단골 6유형 — 코드 → 답 → 이유

1. 슬라이싱 shape

x = torch.arange(12).reshape(3, 4) a = x[:, 1] b = x[:, 1:2] print(tuple(a.shape), tuple(b.shape))

답 — (3,) 그리고 (3, 1)

이유 — 숫자(1)로 뽑은 열 차원은 사라지고, 범위(1:2)로 뽑은 열 차원은 크기 1로 남는다. 행 3은 그대로.

2. 상속·오버라이딩 출력

class Animal: def __init__(self, name): self.name = name def speak(self): print("동물이 소리를 냅니다.") class Dog(Animal): def __init__(self, name, breed): super().__init__(name) self.breed = breed def speak(self): print(f"{self.name}가 멍멍 짖습니다.") Dog("Bori", "Poodle").speak()

답 — Bori가 멍멍 짖습니다. (한 줄만)

이유 — super().__init__(name)으로 name이 생기고, speak는 자식 것만 실행된다. super 줄을 빼면 AttributeError.

3. 모델 정의와 호출

class MyModel(nn.Module): def __init__(self): super().__init__() self.fc = ____(A)____ def forward(self, x): return ____(B)____ y = MyModel()(torch.ones(4, 3)) # 입력 3 → 출력 2

답 — (A) nn.Linear(3, 2), (B) self.fc(x). y의 shape은 (4, 2). model(x)는 __call__을 거쳐 forward 실행.

이유 — Linear는 (입력, 출력) 순서. (B)에 self.fc만 쓰면 층만 돌려주고 계산이 안 된다. __init__은 만들 때 한 번만 돈다.

4. DataLoader 배치

x = torch.arange(20, dtype=torch.float32).reshape(10, 2) y = x[:, 0:1] + 2 * x[:, 1:2] + 3 loader = DataLoader(TensorDataset(x, y), batch_size=4, shuffle=False, drop_last=False) sizes = [] for bx, by in loader: sizes.append(len(bx)) print(len(loader), sizes, by.flatten().tolist())

답 — 3 [4, 4, 2] [53.0, 59.0]

이유 — 10개를 4개씩 자르면 4, 4, 2. for가 끝난 뒤 by는 마지막 batch(16,17 → 53 / 18,19 → 59)의 정답이다.

5. 학습 함수의 역할

optimizer.zero_grad() prediction = model(batch_x) loss = criterion(prediction, batch_y) loss.backward() optimizer.step()

답 — "step()은 저장된 기울기를 이용해 파라미터를 갱신한다"

이유 — zero_grad는 기울기만 지우고, backward는 기울기를 저장만 하고, step이 값을 고친다. 역할을 섞은 보기(backward가 값까지 갱신)는 오답.

6. gradient 손계산

w = torch.tensor(2.0, requires_grad=True) x = torch.tensor(3.0) target = torch.tensor(10.0) pred = w * x loss = (pred - target) ** 2 loss.backward() print(pred.item(), loss.item(), w.grad.item())

답 — 6.0 16.0 -24.0

이유 — pred = 2×3 = 6, loss = (6−10)² = 16, 미분 2(wx−t)·x = 2×(−4)×3 = −24. backward 후에도 w 값은 그대로.

가리고 맞히기 15

x = [[1,2,3],[4,5,6]]일 때 x.sum(dim=0)과 x.sum(dim=1)은?

[5, 7, 9] 그리고 [6, 15]. dim=0은 위아래로 합쳐 열마다, dim=1은 좌우로 합쳐 행마다.

(4, 1) + (1, 5)의 shape은?

(4, 5). 1인 쪽이 늘어난다.

(2, 3) + (2,)는?
(2, 3) + (3,)는?

앞은 불가(오른쪽 끝 3과 2가 다르고 1도 아님), 뒤는 가능해서 (2, 3).

(5, 1, 4) + (3, 1)의 shape은?

(5, 3, 4). 오른쪽부터 4와 1, 1과 3이 가능하고 5는 짝이 없어 그대로.

x가 (3, 4)일 때 x[1:, :2]의 shape은?

(2, 2). 1번 행부터 끝까지 2개, 앞의 2열.

nn.Linear(3, 2)의 파라미터 수는?
nn.Linear(5, 3)은?

8개(3×2+2), 18개(5×3+3).

입력 (4, 3)을 nn.Linear(3, 2)에 넣으면 출력 shape은?

(4, 2). 마지막 차원만 in에서 out으로 바뀌고 batch 4는 유지.

w=0.7, grad=−2, lr=1이면 step 후 w는?

2.7. 0.7 − (1 × −2) = 2.7.

w=3, L=w²이면 w.grad는?

6. 2w = 6.

v=2.0에서
(v**2).backward() 후 (v**3).backward()를 zero_grad 없이 하면 v.grad는?

16.0. 첫 번째 4에 두 번째 12가 더해진다(누적).

샘플 10개, batch_size=4, drop_last=True이면 배치 크기는?

[4, 4]. 남은 2개는 버린다. drop_last=False면 [4, 4, 2].

샘플 90개, batch 20, 30 epoch이면 전체 step은?

150. batch 수 = 올림(90÷20) = 5, 5 × 30 = 150.

batch 크기 4, 4, 2의 loss가 3.0, 3.0, 6.0이면 epoch 평균 loss는?

3.6. (3×4 + 3×4 + 6×2) ÷ 10. 그냥 평균 4.0은 틀림.

prediction (3, 1)과 target (3,)을 그대로 MSELoss에 넣으면?

에러가 아니라 3×3으로 브로드캐스팅되어 틀린 값이 나온다. target.reshape(-1, 1)로 맞춰야 한다.

x.to(device)만 쓰고 저장하지 않으면 x는 어디에 있나?

원래 있던 곳(CPU). x = x.to(device)처럼 다시 저장해야 옮겨진다.
